For F2, the failure-specific consistency check above precedes ALREADY_FAILED; ALREADY_FAILED is not a corruption bypass. On valid history it precedes increment checks. Same-version confirmed failure dominates a concurrent prepared/health success only when the relevant operation meets current identity/fence, binding and original time guards and commits. Expired, fenced, MAX-refused or uncertain failure is not a durable FAILED publication. MAX refusal does not revoke an already stored health row; its original ≤60-second expiry still applies, and a fixed operational alert/investigation is required.

Capture commit/scheduling delays consume the original TTL. No caller/JVM clock, transaction-start timestamp, cached check, successful ping, current-key fallback or publication-time reset can replace the post-wait capture clock. The worker's external check begins after successful capture commit, with no open transaction/business lock; publication also acknowledges only after successful commit. SQL cannot enforce that external ordering by itself: the production client and fixture event ordering must demonstrate the boundary without claiming an external verification actually occurred.
