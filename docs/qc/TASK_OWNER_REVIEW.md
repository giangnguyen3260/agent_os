**QC-04 — P1 UNKNOWN replay becomes available again after a failed authority recheck.** Start from a committed lost reply with a retained frozen command, then click explicit receipt lookup while session/workspace verification returns a network/503 error or malformed workspace DTO. `recover()` calls `fail()`; for these errors `fail()` only clears `verified` and acknowledgment, leaves `frozen` and `denied=false`, and exits busy. `canReplay()` checks only frozen and denied (`:536–537`), so `Gửi lại đúng yêu cầu này` becomes enabled despite unverified current authority. **QC-06 — P2 browser conflict checks can report a false conflict state.** `owner-error` is an unconditional `<p role="alert">{{error()}}</p>` (`HTML:20`); an empty visible paragraph may satisfy `toBeVisible()`. **QC-07 — P2 persisted receipt validation accepts a semantically impossible no-op receipt.** `TaskOwnerService.decode()/validateOwner()` checks individual before/after snapshot structure, scope/event/digest and positive revision, but does not reject identical before/after owners.
