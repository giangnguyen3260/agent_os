## BA clarifications to settle in code and contract

- Read access remains organization-wide ADMIN/MEMBER per supplied contract; conversation/evidence is therefore visible to those readers. Do not imply requester-only confidentiality in UI.
- Ask/reply resumes the approval review state only. It does not resume Task/Mission execution, modify sealed parameters, send notifications or issue a runtime capability.
- Replay must distinguish fresh authorization from mutable request eligibility: state/head expiry must not invalidate an exact previously committed receipt, while revoked grant/membership must deny recovery. Agree original versus current requester binding explicitly if future producers can replace requester identity; no public replacement exists in this slice.
- Detail and information are separate HTTP reads. Repeatable-read per endpoint does not give a shared snapshot across both; FE must reconcile revisions rather than assume simultaneous consistency.
