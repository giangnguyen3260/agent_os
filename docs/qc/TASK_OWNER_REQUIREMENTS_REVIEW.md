Reviewed 2026-10-28 against local HEAD `ef94202` (PR33 closure baseline). ## Selected scope and recommendation

Proceed with an ADMIN-only configuration operation to assign, change or clear the owner of an existing DRAFT Task. Assignment grants no permission, activates no Agent, schedules no work and performs no execution or dispatch. An Agent in DRAFT is a valid configuration owner under existing Task Create behavior; execution readiness must not be inferred from that selection.

Implement a distinct owner context/command/receipt boundary rather than broadening Draft Edit's input DTO. Use a separate owner revision and append-only provenance. Main must settle the policy decisions below before treating the slice as implementation-ready; proposed field names and error categories here are recommendations only.

## Owner context and unavailable projection

Recommend an ADMIN-only repeatable-read context scoped through organization → Team → Mission → Task, with generated time, task/parent display context, owner revision, versioned fingerprint, can-change flag and explicit blockers. Separate the raw stored owner comparison from the safe display projection:

- Internal snapshot distinguishes SQL NULL from a non-null raw reference. Fingerprint the raw value even when no public Agent identity can be returned.
- Public state should distinguish UNASSIGNED, AVAILABLE and UNAVAILABLE. UNASSIGNED means raw SQL NULL; UNAVAILABLE means there is a stored reference that cannot safely be projected. For UNAVAILABLE, return a nullable owner object (or nullable identity/display fields under a precisely specified union) and the state marker. Never expose the name, ID, status, level or Team of a foreign-scope Agent.
- A scoped Agent that is currently ineligible may still be safely identified as the current owner, with explicit eligibility false; do not conflate “displayable” with “selectable.” Unknown/unsafe display data must fail closed to the unavailable projection without echoing arbitrary legacy text.
- Clearing or replacing an unavailable reference should remain possible when the Task and parents permit owner configuration. It must not require the old Agent to be eligible or present in candidate results. Null/null projection alone must never trigger “no change”: compare the raw persisted owner to the requested nullable target.
- Do not silently clear an unavailable reference during GET or context refresh. Do not derive selected owner from the first candidate page. A current owner can be off-page or filtered out.

For the versioned fingerprint, recommend exact scope, raw owner ID, owner revision, task status, task_edit_revision, updated_at and the task/parent source fields used by review/blockers. Include current scoped owner display/eligibility data if the review promises those values are unchanged. Exclude generation time, candidate totals and the whole Agent roster. Define serialization, null handling, timestamp precision and source version explicitly; use a nullable tuple rather than `List.of`/`Map.of` where owner can be null. Target Agent eligibility must always be rechecked at submission even if it is not part of the context fingerprint.

## Candidate paging and parent policy

Use a task-scoped eligible-owner endpoint with the same eligibility predicate in count, page query and mutation: organization + Team + DRAFT/ACTIVE status. Preserve page size 20, stable name/id ordering, escaped literal `%`, `_`, `!` search and bounded page/query inputs. Read count and items in one repeatable-read transaction. Strictly reject duplicate/unknown query parameters and malformed pages; specify whether whitespace is preserved or normalized for query matching. FE must validate exact page/size/count/items, unique IDs and required safe display fields, reset page on search, and fence late responses by scope/search/page/session. Empty roster, no matching results, load failure and blocked parent are different states. A selected candidate remains a proposal, not an authority token.

Recommended conservative parent policy: mirror existing Draft Edit's DRAFT Task, Team DRAFT/ACTIVE, Mission CREATED/READY/RUNNING/WAITING_APPROVAL and unpaused intake gates, with fail-closed unknown states and explicit blockers. This is a consistency recommendation, not inherited product approval. Main must explicitly decide whether paused intake should also block clear and whether existing-task owner configuration should share these creation-related parent restrictions. Do not accidentally require a nonexhausted Mission intake version: owner changes do not create a task or increment that version. Owner revision exhaustion should block fresh mutations, while exact successful replay remains available.

Do not repair invalid/nullable description, acceptance criteria or priority while changing the owner. The existing legacy row must be owner-editable if owner/parent policy permits it; no input-form validity gate belongs here.

## Mutation, locks and replay ordering

Recommended transaction under READ_COMMITTED, using the same organization mutex as current configuration writes:

1. Strictly parse one JSON command, exact allowed fields, required explicit nullable target owner, expected owner revision/fingerprint and one canonical UUID idempotency key. Reject missing owner separately from explicit null, duplicate keys, extra lifecycle/input/dependency fields, coercion, trailing JSON, invalid UTF-8, oversized body and unsupported media type. Reuse parser conventions, not another feature's command DTO.
2. Lock organization, account and membership in existing order; validate enabled account, credential version and current ADMIN membership. Resolve/lock exact Team, Mission and Task scope. Never trust only the session role or a context response.
3. Recheck authority after these waits and look up the receipt scoped by organization/Team/Mission/Task/actor/key. Digest must include a versioned operation domain, full scope, actor and full canonical command including expected tokens and nullable target. Same key + different digest conflicts; exact match returns the immutable saved receipt before current mutable blockers, stale-source checks or candidate eligibility. A receipt is a historical result, not a current detail response. Replay must not depend on the Agent remaining eligible.
4. For a fresh command, lock required existing scoped old/new Agent rows in deterministic UUID order after parent/task locks. Do not query/lock a foreign-organization old Agent to obtain a display name. Recheck authority after all additional waits, then recompute the source snapshot and validate expected revision/fingerprint, parent/task blockers, target eligibility and raw-value no-op. The organization mutex serializes compliant roster/configuration writes; preserve it through commit. Do not introduce an Agent-first lock path. A missing/foreign/ineligible proposed target returns a generic configuration conflict without revealing foreign records.
5. Update only owner_agent_id, owner revision and updated_at, with full scope and expected owner revision guard. Atomically append owner event, owner receipt and minimal safe audit. Any failure rolls back all four effects. Return one immutable receipt; no follow-up read should rewrite its historical values.

A read-only receipt lookup must freshly authorize ADMIN and exact Task scope before returning an actor-scoped receipt or absence. Denied replay/lookup must reveal no saved owner information. Existing Task Create's receipt-before-parent-lock ordering is not the strongest template here; prefer Draft Edit/Team Settings' scoped resolution and post-wait authorization discipline.

## Separate revision, provenance and side-effect boundary

Recommend owner revision default 0, nonnegative, checked overflow; separate owner event/receipt tables modeled on V017, with scoped Task FK, unique per-task owner revision, actor FK, scoped actor/key receipt PK and receipt-to-event FK. Do not overload task_edit_revision, task_edit_events, task_edit_receipts or Agent configuration revisions. Preserve all preexisting Task rows and creation receipts unchanged.

Owner event/receipt should record event ID, revision, actor, server time, before and after nullable owner references plus safe availability-aware display snapshots if the contract needs human-readable review. Never resolve historical foreign raw references to expose identities in public receipts. Main must specify internal raw provenance versus public safe projection so clearing an unavailable reference is auditable without cross-scope leakage. Serialize nulls explicitly. Audit payload should contain only eventId/revision (as Draft Edit does); event type and owning history remain distinct from TASK_DRAFT_UPDATED. Task activity can then display the new audit event without moving it into input-edit history.

A successful owner change must leave title, description, acceptance criteria, priority, dependencies, task status/pending fields, created_at, task_edit_revision, Mission intake version/pause, Mission/Team/Agent rows, runtime/dispatch/grants/approvals and existing histories/receipts untouched. updated_at and owner-specific records are the intentional exceptions. A rejected request or replay must have no new business effects. An owner change invalidates old Draft Edit context via owner ID/updated_at; recommend reciprocal owner-context conflict after an intervening input edit via task_edit_revision/updated_at. Do not auto-merge either stale review.

## Screen-by-screen BA/FE acceptance recommendations

| Surface | Required behavior |

| Owner picker | Search and page server results; keep selection independent of current page, show load/empty/error states, prevent stale result selection after scope/auth changes. |
| Review | Display assign/change/clear intent, safe before/after identities or unavailable marker and configuration-only scope. Require renewed review after changed context or selection; do not erase unrelated nullable input fields. |
| Submit/conflict/blocked | Fresh authority/context preflight, immutable submitted body/key, no double submit. Conflict reload requires deliberate review; never silently replace expected tokens and resend. |
| Unknown outcome/recovery | Preserve the original in-memory body/key; explicit actor-scoped receipt lookup or exact retry. Absence is not proof of failure. No new key until outcome is resolved; no sensitive browser persistence or automatic mutation retries. |
| Saved/authority loss | Render validated historical receipt, then refresh live detail separately. Logout/account/scope/ADMIN loss clears private context, selection, frozen command and receipt; epoch fences prevent late responses restoring them. |

## Decisions/blockers for main's contract and QC evidence

These are contract/evidence gates, not confirmed defects in unimplemented code:

1. Define nullable UNAVAILABLE semantics and public receipt/history redaction for a non-null out-of-scope raw owner. Existing Task Detail's pair cannot express it safely.
2. Freeze parent and intake-pause policy, target eligibility (including intentional lack of level restriction), no-op behavior, owner revision overflow and reciprocal input/owner fingerprint conflicts. No historical product approval is asserted for these decisions.
3. Freeze separate owner revision/event/receipt constraints, exact command digest/replay semantics and post-wait authority checks, including replay after Task/parent/Agent eligibility changes.
4. Require real PostgreSQL evidence for same-key identical/different-body races, different-key stale writers, assign/clear versus Team Settings removal, candidate mutation while waiting, input-edit versus owner-change races, and account disable/credential rotation/role loss while blocked on locks. Expected valid serial outcomes must be specified; a roster removal must not detach an owner referenced at its commit, and assignment must not accept an Agent removed first.
5. Require all-or-nothing rollback evidence when event/receipt/audit insertion fails; no-op/invalid/denied/stale/blocked/exact-replay snapshots must prove unchanged inputs, dependencies, lifecycle, Mission intake and runtime data. Authentication bookkeeping should be considered separately from business mutations.
6. Require legacy nullable input preservation, unknown parent states, unavailable/foreign owner redaction, current ineligible owner replacement/clear, off-page selection, search escaping/bounds, strict wire and receipt validation, permission-loss clearing and late-response races. Review editor/picker/review/saved/blocked/conflict/unknown/recovered/denied states at desktop/tablet/mobile widths using actual implementation evidence.
