## Read-only independent native-probe review

Reviewed `scripts/task-owner-history-probe.py` after main reported it complete. No probe, production, fixture or workflow changes were made. This is source/oracle review, not a native runtime result. Two concrete false-positive risks remain in the probe's evidence claims:

1. **P1 — zero-write oracle is incomplete (`snapshot`, `reject`).** `snapshot()` excludes `human_accounts` and `organization_memberships`, which hold business identity/authority data, alongside the actual authentication/session tables. A rejected GET could change a display name or membership without this snapshot detecting it. For included tables, only row-value MD5 digests are compared: an UPDATE that writes the same values, or an insert/delete leaving the same final values, is invisible. Thus its printed `zero business writes` conclusion establishes final row-value equality for the included tables, not absence of writes. Suggested main-owned correction: include identity/membership rows, compare tuple transaction identity for same-value UPDATE detection, and use an appropriate write-observation mechanism if literal zero writes is required. Browser xmin/ctid coverage remains limited to its nine scoped tables; it does not close these native gaps for all organizations/tables.
2. **P1 — rejection privacy oracle drops evidence (`Client.request`, `reject`, GET-body check).** `Client.request()` replaces every non-JSON response body with `{'nonJson': True}`. `reject(...,403/404/400/405)` normally asserts only status and final DB state; it does not reject private JSON bodies or validate a safe error envelope. Consequently an HTML403 containing a foreign owner or SQL diagnostic passes after its body is discarded, and a JSON403 containing private fields also passes. The selected-corruption500 branch checks a code and two literal substrings, leaving other private values/diagnostics unchecked; the body-bearing GET check inspects status only. Suggested main-owned correction: retain raw bytes internally, assert expected safe response type/envelope and explicit sensitive-value absence, and keep raw bodies out of failure output. Logging avoidance should not erase oracle input.
