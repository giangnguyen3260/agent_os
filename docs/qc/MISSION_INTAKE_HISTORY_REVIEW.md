### QC-H1 — P2: frontend accepts forbidden C1 controls in history names

Location: `frontend/src/app/features/mission-intake/mission-intake-validation.ts`, `text()` at line18, consumed by `validHistory()` for actorName/teamName/missionTitle and by the history component for workspace name. Its single-line rejection covers U+0000–U+001F and U+007F, but omits U+0080–U+009F. Thus `actorName: 'unsafe\u0085name'` is accepted and rendered instead of causing private clearing/error. Backend `historyName()` rejects this exact character with `Character.isISOControl`; `eligibleUnsafeActorNameFailsClosed` explicitly includes U+0085. This is a frontend strict-decoder contract mismatch, not evidence that the current backend emits such a name.

Evidence: an isolated in-memory transpilation of the existing production validator returned `text('unsafe\u0085name',255) === true`. No source was changed. The frontend harness's unsafe-name cases cover newline and surrogate but omit C1; the frozen browser malformed-actor case uses U+0001, so neither catches this mismatch. Main should reject the same forbidden control set in history name validation and add a targeted C1 assertion in its owned validator tests. Do not weaken the backend rejection.

### QC-H2 — P2: probe order oracle loses nanoseconds

Location: `scripts/mission-intake-history-probe.py`, `instant()` lines91–93 and `history()` lines130–132. Python `datetime.fromisoformat` truncates fractional seconds beyond six digits, while the probe accepts up to nine. Distinct instants `.123456789Z` and `.123456788Z` become equal; the oracle then compares eventId as though they were a timestamp tie. With suitably descending UUIDs, a wrongly ordered submicrosecond pair passes; a correctly ordered pair with opposite UUID order can fail. An isolated standard-library expression confirmed those two parsed datetimes compare equal. Production frontend `instantKey()` preserves nine digits correctly; PostgreSQL current writer timestamps have six digits, so this is a probe precision limitation rather than an observed backend failure.

Main should compare a full normalized seconds/nine-digit-fraction key (or exact epoch nanoseconds) and retain UUID descending only for actual equal instants. Existing tie fixture checks equal six-digit timestamps and does not exercise this oracle defect. The concatenated pages should also have their complete ordering checked; current `history()` checks each page separately and normal first/second-page assertions check set equality/disjointness without checking the boundary. The tied-fixture global UUID assertion does correctly cover the all-tied boundary.

### QC-H3 — P2: probe strict UUID/name validation can report false success

Location: `scripts/mission-intake-history-probe.py`, `history()` lines124 and131. `[0-9a-f-]{36}` accepts36 hyphens and arbitrary hyphen placement, and does not enforce UUID version1–5 or RFC variant. The actor check accepts any string, including blank, forbidden controls, unpaired surrogates and256-code-point names. Isolated regex evaluation confirmed36 hyphens pass. Main should apply canonical UUID and safe nonblank255-code-point checks before claiming strict DTO validation. Accepted-receipt provenance comparison protects against changing only the history eventId in this particular run, but it is not an independent canonical validation of either writer or reader output. Backend decoder and frozen browser validator already enforce canonical UUIDs; frontend name controls still need QC-H1.
