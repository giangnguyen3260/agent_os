## Bounded review and verification gates

All gates below are **required, unexecuted**. Contract acceptance requires unambiguous rules; implementation acceptance later requires source plus correctly attributed completed evidence.

| Gate | Required behavior and discriminating acceptance cases |
|---|---|
| G1 — Public allowlist | A dedicated DTO contains only the exact fields below. Internal Metadata/Page/Reference, external locator/version, verifier, HMAC versions, integrity/health rows and implementation exception data never appear, even as null properties or nested objects. Assert exact recursive key sets and JSON types for successful empty/populated pages, every provider and UNAVAILABLE rows. Annotation-only suppression or searching for one secret sentinel is insufficient. |
| G2 — Genuine absence versus storage failure | Missing/stale/unusable health, missing/malformed credential storage and known integrity failure yield readable safe connection metadata with `UNAVAILABLE`/null mask. Absent observation is data absence, not a missing table, failed SQL, timeout, wrong transaction context or failed commit. Such infrastructure failures return fixed503 without a fabricated empty page, per-row downgrade or cached success. Invalid connection metadata fails the complete projection safely503; GET never repairs or silently skips it. Exercise absent row and unavailable relation separately; include a mixture of good and credential-unavailable rows. |
| G3 — Fresh database time | One fresh statement-level PostgreSQL clock sample inside the RR read is shared across all selected rows; no JVM clock or RR transaction-start `current_timestamp` can extend freshness. Require finite timestamps and `observedAt <= now < validUntil`, with validity at most60s from observation, including equality and future-time rejection. A transaction begun before expiry but sampled after expiry must show UNAVAILABLE. A page spanning boundary rows uses one sample. H2 can cover structure/boundary arithmetic only. |
| G4 — No re-aging | Publication stores the original observation time and bounded original deadline. Delay publication across expiry, republish the same observation, deliver an older success after a newer failure, and supply future/malformed/infinite timestamps. None may renew freshness or replace newer evidence incorrectly. Sample publication DB time after any locking wait. No remote check or secret/HMAC call occurs while holding a transaction/lock. Freeze equal-time duplicate/conflict behavior, including no mutation on rejection. |
| G5 — Integrity provenance and scope | PRESENT requires authenticated-at-write evidence for the exact immutable active credential plus fresh usable health and no known integrity failure. Merely constructing syntactically valid Metadata or finding a verifier/reference does not create integrity evidence. Cross-org/connection/provider/revision and same-scope locator/external-version/HMAC-version substitution cannot reuse evidence. ## Exact public data gate

Success envelope is exactly `{data,meta}`, meta exactly `{requestId}`. List data exactly `{organizationId,page,pageSize,total,items}`; `pageSize` is numeric20. Each Connection exactly:

`{organizationId,id,provider,credentialMode,name,options,state,revision,credentialRevision,credentialState,credentialMask,createdAt,updatedAt}`.

Provider/mode/options mapping is OPENAI/OPENAI_API_KEY/`{}`, ANTHROPIC/ANTHROPIC_API_KEY/`{workspaceId}` (required nullable member), GOOGLE_GEMINI/GEMINI_API_KEY/`{}`. State ENABLED|DISABLED; credentialState PRESENT|UNAVAILABLE. The mask is exactly eight U+2022 bullets (`"••••••••"`) only for PRESENT and explicit JSON null otherwise; never prefix/suffix/length/fingerprint. No policyRevision, checkedAt, currentObservation, health timestamp, grant, connected flag or credential reference is added to Connection/List. Error envelope exactly `{error,meta}`, error exactly `{code,message,details}`, details always `{}`. Reuse the PR46 fixed public error set/messages rather than leaking internal persistence/publication codes.
