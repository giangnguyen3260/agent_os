## Findings

1. **Low — misleading empty-group message on a beyond-last page.** `frontend/src/app/features/approvals/approval-list-page.component.html:182-200` renders “No approval records in this group” whenever the page has no items, even with `total=24` and `page=100000`. Previous only decrements one page; there is no direct first-page action in this state. This also occurs when records leave a group and its last page disappears. Distinguish an empty page from an empty group and offer a first-page reset. AC03 currently asserts the misleading message (`frontend/tests/e2e/approval-center.spec.mjs:61-70`). Nonblocking; no data disclosure or mutation.

2. **Low — authorization preflight has no bounded wait/recovery.** `frontend/src/app/features/approvals/approval-list-page.component.ts:110-125` awaits `AuthService.getWorkspace()` before the approval request; that shared method (`frontend/src/app/core/auth/auth.service.ts:156-167`) has no timeout. The approval service's 30-second timeout does not cover it. A stalled workspace response leaves loading active with no retry control because context is still null. Bound the preflight wait and expose recovery. Scope/account epochs still discard late results; this is an availability/UX issue, not an authorization bypass.

## Source conclusions

- Service authorization rechecks enabled human identity, credential version and ADMIN/MEMBER organization membership inside the read transaction (`ApprovalCenterService.java:31-48`); the existing security chain also checks live credentials and organization membership. ADMIN read access is not a decision grant. Controller adds only GET; the DTO explicitly projects metadata, with no payload, policy snapshot, human decision reason, provider call or execution claim.
- Counts and page reads share REPEATABLE_READ; organization predicates, closed enum SQL fragments, bound parameters, limit 20 and `created_at DESC,id` ordering are present. Offset pages are separate observations: concurrent inserts/status changes may move records between successive requests; this is not a cross-request snapshot guarantee.
- V010 references existing composite unique keys from V004/V007/V009; its Team/Mission/Task FKs and Task-requires-Mission check prevent mixed scope. Requester FK intentionally permits same-org movement; the projection additionally checks current Team and scrubs both ID/name when unavailable. Status/risk/title/action/timestamp constraints are present. The migration adds no seed or producer. Safe metadata content remains a future producer responsibility; schema field names/lengths cannot establish that arbitrary strings contain no secrets.
- Component clears rows/counts/inspection before loads, unsubscribes approval requests, and checks epoch/account/destroy state before accepting responses. Validation rejects unexpected row/page/count fields, foreign organization IDs, inconsistent totals/page lengths, invalid references/statuses and duplicate IDs. Interpolation and scoped router links avoid raw HTML/action execution. No localStorage authority was introduced. Normal read freshness is explicit manual refresh, not live revocation of already displayed metadata.
- HTML/CSS provide labelled compact cards, wrap long fields, preserve actual closed statuses, explain read-only semantics and use a native modal menu with Escape/focus handling. Responsive rendering and actual focus behavior require the coordinator's browser/visual gate.
