## Source findings

- `backend/src/main/resources/db/migration/V018__mission_intake_controls.sql`: scoped receipt primary key includes actor and idempotency key; event ID is globally unique. `original_response` is text, with no database JSON-shape or transition constraints. Human FK alone does not establish current organization membership. At the reviewed baseline, the scope prefix supports scoped lookup but there is no dedicated history ordering index. The frozen contract pins V019 on `(organization_id,team_id,mission_id,created_at DESC,event_id DESC)` to support the bounded scoped chronological query. The earlier assertion that no migration was authorized was incorrect: index-only V019 is Main’s authorized engineering decision, not a reviewer permission gate.
- `backend/src/main/java/com/agentos/missionintake/MissionIntakeService.java`: `update` writes one original response, receipt timestamp, Mission change and audit event atomically. `stored`/`receipt` intentionally restrict recovery to the requesting actor. `decode` checks exact JSON shape, types, scope, event ID, canonical int64 versions, increment-by-one, flipped boolean and parsable time. It validates digest format but cannot authenticate the response from that command digest. It does not compare response time to row `created_at`.
- `backend/src/main/java/com/agentos/mission/application/TaskCreateService.java`: successful creation also increments `task_intake_version`. Intake receipts are a sparse subset of this shared counter. Gaps are legitimate; do not demand adjacent history entries have consecutive versions, invent missing events, or label versions as intake-change counts.
- `backend/src/main/java/com/agentos/taskediting/TaskDraftEditService.java`, method `history`: useful precedent for fresh ADMIN authorization, exact parent resolution, repeatable-read count/page and fail-closed selected-page decoding. Its global `human_accounts` join does NOT enforce this slice's current same-org actor-name restriction and must not be copied unchanged.
- `docs/engineering/TASK_EDIT_HISTORY_CONTRACT.md`: fixed page size 20, strict page parsing, explicit current-name caption, lifecycle-independent reads, stale-response fences and fresh-snapshot offset caveat are reusable requirements. Task edit integer revision ordering is not directly reusable as receipt ordering.
- `backend/src/main/java/com/agentos/missionintake/MissionIntakeSecurity.java` and `MissionIntakeController.java`: existing intake subtree has fresh transport ADMIN interception before controller parsing; existing context/receipt routes reject every query. Add history parsing locally without weakening those existing routes.

## Contract-resolved decisions and implementation acceptance conditions

### B1 — Current same-org actor-name projection (privacy)

Resolve an actor display name only when the receipt's actor still has a current membership in the receipt organization and a corresponding human account. Use an organization-scoped membership predicate/EXISTS or a correctly constrained LEFT JOIN. Never fall back to a global account name, email, UUID, old name, audit payload or receipt key. Do not require the historical actor still be ADMIN: a current MEMBER remains a same-org human. Viewer ADMIN and historical actor eligibility are separate checks.

Frozen Main decision: exact field `actorName` is nullable and membership-based. Current same-org MEMBER and disabled human accounts remain name-eligible; removed membership yields explicit null. UI null label is `Không còn thông tin người thay đổi`. Preserve receipt and total when membership is removed; an inner join that drops receipts is unacceptable. Non-null names must be safe nonblank text <=255 code points with no forbidden controls/unpaired surrogates; malformed eligible names fail the selected page closed. The caption identifies names as current rather than historical identity snapshots. No actor-policy decision remains open in the contract.

### B2 — Original provenance and corruption policy

History is organization-admin-visible across all actors within the exact Mission scope; do not reuse own-actor receipt recovery filtering. Project only allowlisted receipt fields plus the safe current name. Keep original `versionBefore`, `versionAfter`, `pausedBefore`, `pausedAfter`, and `committedAt` from the original response. Do not calculate before-values from current state or neighbors.

Require strict JSON decoding equivalent to existing `decode`: reject duplicate/unknown/missing keys, trailing content, null/wrong types, noncanonical IDs, wrong scope/event ID, malformed/overflow versions, nonincrement transitions, unchanged paused state and invalid time. Catch stored-data parsing failures as a safe 500 unavailable response, never client 400, raw JSON, exception or SQL detail. Return no partial items and never skip corrupt rows. Count includes actual scoped receipts; structural checks cover the selected page, not an unclaimed global integrity scan.

Frozen Main decision: parsed `committedAt` must represent the same instant as row `created_at`; compare instants rather than timestamp spellings. The baseline writer uses microsecond precision. The writer uses the same timestamp for both. Never silently replace response time with row time. The frozen safe error code is `MISSION_INTAKE_HISTORY_UNAVAILABLE` with status 500. Format validation/digest syntax is not cryptographic verification or database-enforced immutability; do not claim either. No receipt repair is in scope.

### B3 — Deterministic paging without version fabrication

Frozen Main decision: deterministic total ordering is receipt row `created_at DESC, event_id DESC`; use the same ordering for SQL selection and UI expectations. Timestamps can tie, so time alone is insufficient. Do not sort decimal versions lexicographically or cast unvalidated JSON during SQL ordering. The contract pins recorded-time order, without a version-order guarantee across clock corrections: `committedAt` is captured before transaction commit, not an independently measured wall-clock commit-completion time.

The frozen contract pins fixed pageSize 20, optional canonical decimal page default 0, range 0..100000, reject duplicate/unknown queries and GET bodies. Reject noncanonical scoped UUIDs according to existing strict wire rules. Count/page/name lookup/authorization and scope resolution must share one read-only repeatable-read transaction. Empty and out-of-range pages return empty items and actual total. Never count only receipts with eligible actor names. Versions remain decimal strings in Java/JSON/TypeScript and rendering; use validated BigInt only if numeric comparison is necessary, never JavaScript Number.

Offset pages are fresh snapshots: concurrent inserts can shift later pages, producing repeats/omissions across requests. State that limitation in contract/UI; claim no duplication only for a static dataset. No cursor or persistent snapshot is promised; V019 is the authorized supporting index. The contract pins total to integer 0..Number.MAX_SAFE_INTEGER; enforce that bound and fence unexpected lengths, duplicates, bad scope and malformed items before display. Do not assert consecutive versions or a globally alternating flag sequence across receipts.

### B4 — Fresh viewer authority and UI data lifetime

Every history request must freshly verify enabled human account, matching credential version and current organization ADMIN before exposing receipt existence/count/content; then resolve exact organization/Team/Mission parents. Preserve existing 401/403 transport precedence and 404 wrong-parent behavior. Do not gate read access on current intake pause, lifecycle eligibility or revision exhaustion. Another current ADMIN may read actual receipts; MEMBER, former ADMIN, disabled/stale viewer and foreign scope must not.

Initial load, refresh, pagination and focus/visibility return must recheck session identity and raw workspace ADMIN authority. Clear visible history before authority refresh and on hidden tab, identity/scope/auth loss and destruction; persist neither data nor authority in browser storage; cancel or generation-fence late replies including destruction. A cached ADMIN navigation link is not authorization. Validate exact DTO keys, UUIDs/scope, time, booleans, version strings/ranges and page consistency. Escape names/text and use no raw HTML. Show loading, empty, denied, unavailable and out-of-range states with scoped back navigation. Show both paused values and both versions without implying execution was paused, resumed or cancelled. No save/retry-command/runtime action belongs on this screen.

## Frozen API and UI alignment

Main pins GET `/api/v1/organizations/{org}/teams/{team}/missions/{mission}/task-intake/history?page=0` and exact response data keys `{organizationId,teamId,missionId,teamName,missionTitle,page,pageSize,total,items}`. Item keys are exactly `{eventId,versionBefore,versionAfter,pausedBefore,pausedAfter,committedAt,actorName}`. Team/Mission names must be actual safe stored strings. These fields and count bounds are settled requirements, not pending recommendations.

The UI route is `/workspace/:id/teams/:teamId/missions/:missionId/intake/history`, with `Lịch sử nhận task` heading/link and scoped links to Mission Control and intake controls. Refresh/retry is GET-only. Frozen verification additionally requires actual populated, second-page, empty, error and denied states at all three widths, backend/PostgreSQL/browser evidence tied to the tested tree, no reused counts and no execution claim from discovery. No new Figma-frame claim, merge or deployment is included.

## Required review evidence for Main/QC

1. Actual persisted flips by at least two actors; replay does not add rows. Unrelated task creation produces legitimate version gaps. No-receipt legacy Mission stays empty, including if current intake state/version is nonzero.
2. Same-org ADMIN viewer sees both actors; rename shows current name. Actor becomes MEMBER, leaves organization, or is disabled: verify the pinned name policy without dropping receipt/count. Foreign-only actor identity never leaks. Safe long/unicode names render escaped; invalid eligible stored names follow the corruption policy.
3. Unauthorized, disabled, stale-credential, revoked-role, foreign-organization and wrong-parent requests expose no business data. Archived/terminal/paused/exhausted current state does not hide authorized history.
4. At least 21 receipts with tied timestamps exercise deterministic static pagination, actual totals, empty/out-of-range pages and documented concurrent-insert shifts. Verify canonical page/IDs, duplicate/unknown query/body rejection and >2^53 version strings through Long.MAX_VALUE; numeric JSON versions must fail validation.
5. Corrupt original JSON/field shape/types/scope/event/version/boolean/time and timestamp mismatch exercise safe selected-page failure without raw provenance disclosure or partial success. A corrupt row outside the selected page must not be represented as globally validated.
6. Held responses across account, scope and authority changes cannot restore cleared content. Responsive keyboard-readable loading/empty/error/denied/populated/paginated screens at 1440/768/390; truthful current-name and paging captions.
7. Demonstrate history reads do not change Mission flags/versions/timestamps, receipts, audit business events, tasks or runtime state. Preserve existing context/receipt wire rules and intake update/replay semantics. Bind all new results to the actually tested tree; no inherited runtime pass claim.
