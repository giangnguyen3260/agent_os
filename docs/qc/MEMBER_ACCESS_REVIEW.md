### Concrete findings to main/workers

- **MA-L01 Medium — OPEN, literal search escaping is disabled in generated SQL.** `backend/src/main/java/com/agentos/governance/application/MemberAccessService.java`, inventory filter, writes Java text-block SQL `escape '\'`. Java consumes the backslash as the escaped single quote, yielding SQL `escape ''`; PostgreSQL therefore has no escape character while the pattern builder inserts backslashes. Literal percent/underscore/backslash searches return incorrect results. Fix the Java source to preserve the backslash in the SQL escape string (double the source backslash), or choose an explicit non-backslash escape character and escape it consistently in the pattern. Run actual PostgreSQL searches for all three characters. This is source analysis, not an executed SQL failure.
- **MA-L02 Medium — OPEN, timestamp precision can reject a valid grant response.** `frontend/src/app/features/members/member-access.service.ts`, validGrants(), compares Date.parse(expiresAt) to Date.parse(generatedAt). PostgreSQL/Java timestamps retain submillisecond precision; Date.parse truncates to milliseconds. A grant expiring later within generatedAt's millisecond is correctly UNEXPIRED on the server but classified EXPIRED by FE, causing the whole page to fail closed. Fix comparison using a shared exact timestamp comparator preserving fractional precision, or explicitly align server classification and serialized timestamps to a documented common precision. Add a same-millisecond/different-fraction response oracle and exact equality. No browser execution performed.
- **MA-L03 Medium — OPEN, FE query length disagrees with backend.** `frontend/src/app/features/members/member-access.component.ts`, load(), rejects raw UTF-16 query.length >200, while backend validates stripped Unicode code-point count. A URL containing101 supplementary Unicode characters (202 UTF-16 units) is rejected in FE although valid under the backend's200-code-point bound; a padded query can also be rejected before stripping. Normalize/count consistently with the contract/backend before enforcing the bound; cover direct URL reload as well as form submission. Resolve the contract's intended Unicode whitespace set explicitly rather than relying on differing Java strip()/JS trim() semantics. Source-only finding.

No blocking unauthorized-read defect observed in the inspected incoming backend source. These three concrete correctness issues remain open pending worker correction; final security/UX disposition awaits completed source and actual evidence.
