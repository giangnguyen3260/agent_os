The existing owner contract expressly excluded history from its earlier slice; the present authorization selects that next slice without reopening owner mutations.

Use actual scoped V020 `task_owner_events` as the history source. V020 retains old owner pointers and initializes owner revision to zero; neither an existing assignment nor revision zero proves a recorded change. Do not synthesize an initial assignment, baseline event, legacy actor or event from current state, audit payloads or receipts. History must not require an own-actor receipt: it lists recorded changes by all actors in the authorized task scope. Do not change owner write/replay behavior, runtime, grants, dispatch or write eligibility.

Task edit history supplies revision ordering and page-local validation precedents. Mission intake supplies the stronger removed-membership actor privacy precedent. Its receipt-backed source and timestamp ordering should not be copied: owner events already have unique positive scoped revisions and before/after snapshots.

## Decoder and UI risks requiring explicit acceptance

1. Validate exact stored owner/Agent keys, duplicate keys, trailing tokens, types and explicit nulls without scalar coercion. Validate canonical event/Agent UUIDs, positive bounded revision, nonnull recorded timestamp and safe text (name <=255; level/status <=50; no forbidden controls or unpaired surrogates). Before ASSIGNED status may be safely stored but currently ineligible; after status is validated as recorded DRAFT/ACTIVE, never rechecked live. Reject missing fields and unsafe actor/context names rather than sanitizing them into invented history.
2. Validate internal raw pointer provenance without serializing it: UNASSIGNED requires raw null; ASSIGNED requires matching nonnull raw ID; UNAVAILABLE before requires nonnull raw ID and null public Agent. Raw before/after must differ. In particular, UNAVAILABLE→UNASSIGNED is a genuine clear even though both public Agent values are null. Distinct-ID assignments remain changes even when display names match. Existing receipt `decode` contains useful owner/provenance rules but requires receipt/digest/time joins; making history depend on that own-receipt decoder would select the wrong source and scope.
3. Historical snapshots are structurally checked recorded data, not cryptographic proof or a database immutability guarantee. Do not rebuild them from live agents to claim stronger provenance. A later foreign-Team move does not invalidate the originally recorded scoped snapshot.
4. Recommend ADMIN Task Detail history access in every lifecycle state, independent of whether the owner editor is available. Show actual scope, newest-first revision/time, recorded before/after owner state, current actor caption, actual count and GET-only paging/refresh. Empty wording should mean “no recorded owner changes,” not “never assigned.” No review checkbox, save control, candidate chooser, baseline selection or automatic POST belongs here.
5. Follow Mission intake private-history fences: clear private data before fresh session/raw-workspace ADMIN checks on load/refresh/focus/visibility/paging, on hidden/auth/account/scope loss and destruction. Cancel and fence late successes and errors by request epoch, scope and actor. Strictly validate exact response shape, requested scope/page, item count, states, IDs, ordering and nullable actor. Escape text; no browser persistence of private history or authority. Explain that offset pages are independent snapshots and concurrent changes can shift/repeat rows across requests; no cursor guarantee.
