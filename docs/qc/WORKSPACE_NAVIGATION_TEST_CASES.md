Native confirm uses an owned one-shot dialog listener, awaits handler completion and removes exactly that listener in `finally`. No `window.confirm` replacement or guard changes.

Every case asserts zero organization API non-read requests and unchanged read-only database snapshots, including tuple identity to detect same-value UPDATEs. Snapshots cover human accounts, all business command receipts/configuration/ledger/event tables, organization invitations and their events/receipts, organizations, memberships, teams, missions, tasks, agents, dependencies, task owner events/receipts, task edit events, audits, approval requests, action heads, snapshots, grants, decisions, receipts, and information entries/receipts. Authentication attempts/audits, session tables, password recovery/rate-limit tables, and mail transport/locking tables are excluded. The bound is committed table state including PostgreSQL xmin/ctid; this does not claim to observe rolled-back transactions.
