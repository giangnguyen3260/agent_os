## Contract alignment

Read [UI flow](PROVIDER_CONNECTION_UI_FLOW.md) and [API contract](PROVIDER_CONNECTION_API_CONTRACT.md) together. Provider selection is explicit; no default provider is inferred. Create forms differ by selected direct credential profile. A generic review frame uses labelled dynamic placeholders; the implementation must preserve the actual provider/name/options through review and receipt, not substitute the OpenAI detail specimen. There are no executable prototype reactions or working controls: these are static editable design specimens.

List shows only connection metadata, not check summaries unavailable in its DTO; unsupported search was removed. Access-check and model-discovery are distinct explicit actions with distinct observations and historical snapshots. Discovery includes COMPLETE/TRUNCATED, empty-data placeholder and paging; no hardcoded model ID or price is presented. Accepted-check progress, denied/failed and UNKNOWN states are separate from a lost metadata-save response. Leaving a check view does not cancel accepted backend work. Save/rotate/enable never invokes a provider automatically. Runtime generation remains explicitly unavailable until its separate authority/budget slice.

Placeholder braces and named sample connections are design content, not real records, seeded production data or successful live checks. No real key/customer data was used. Credential entry is represented by a placeholder and save review by a constant entered-key marker; the actual implementation must mask typed content and never reveal stored keys.

## Visual validation and limits

Coordinator viewed the final desktop detail, tablet list, mobile Claude create, mobile explicit provider selection, mobile metadata-command UNKNOWN and mobile remote-check UNKNOWN compositions after typography/style fixes. Six original PNGs are retained locally for independent review. The earlier mobile discovery result was also inspected after multiline sizing correction; later shared text-style changes are covered structurally, not claimed as a second visual pass on that particular frame. The other frames were structurally checked, not all individually screenshot-reviewed.

Two real composition issues were corrected: button labels had inherited narrow fixed widths, and several multiline text blocks had fixed single-line heights. Buttons now fill available label width; text uses HEIGHT resizing after layout sizing and shared Forest styles. Final recorded geometry has no such findings. Independent document/six-capture retest outcome belongs to [QC review](../qc/PROVIDER_CONNECTION_DESIGN_REVIEW.md), not inferred from this coordinator report.

No browser, keyboard/screen-reader, live provider, KMS, PostgreSQL or cost test was executed by creating these designs. No production UI, endpoint or Figma pixel-parity implementation is claimed. Before coding, freeze the corrected API/security/UI contract and take its exact DTO/authority/UNKNOWN rules into the feature; each UI action still needs real runtime tests and independent acceptance.
