# Mission task intake controls

Stack on PR31 closure5597bac2822107f2bb47892982148f27b4bd1ffc. ADMIN can review and change whether a scoped Mission accepts new task creation. The existing Task Draft Edit policy also blocks fresh edits while intake is paused; the UI must explicitly describe that consequence. Existing tasks/status/owners/dependencies/pending/run/approval state remain untouched. This does not implement execution Pause Mission, dispatch suspension or cancel. Existing disabled runtime actions stay distinct.

## API

Root `/api/v1/organizations/{organizationId}/teams/{teamId}/missions/{missionId}/task-intake`. All GET/POST/receipt reads freshly check enabled matching-credential organization ADMIN, then exact scoped Team/Mission;401/403 transport follows existing security before strict controller parsing,404 wrong parents. Member existing Mission views remain unchanged.

GET exact data keys `{organizationId,teamId,missionId,checkedAt,teamName,missionTitle,teamStatus,missionStatus,intakePaused,intakeVersion,fingerprint,canChange,blockers}`. Version is a canonical decimal **string**0..9223372036854775807 to avoid JavaScript rounding. Fingerprint is SHA256 of one versioned canonical ordered tuple including scope, Team name/status, Mission title/status, intake flag/version and Mission updated_at. GET is read-only repeatable-read.

POST exact `{expectedVersion,expectedFingerprint,paused}`: canonical decimal string version,64lowerhex fingerprint, JSON boolean. Strict duplicate/unknown/type rejection, valid UTF8 JSON application/json, single canonical lower RFCUUIDv1-5 Idempotency-Key, body<=4096bytes, no query. GET endpoints reject all queries and bodies; IDs canonical as existing task edit wire. First201/replay200. Errors400 BAD_REQUEST;409 MISSION_INTAKE_CONFLICT stale version/fingerprint, MISSION_INTAKE_BLOCKED eligibility, MISSION_INTAKE_NO_CHANGE same current flag, IDEMPOTENCY_CONFLICT same key different canonical body. Malformed persisted receipt safe500 MISSION_INTAKE_UNAVAILABLE; no raw source or generic error dispatch leak.

Receipt exact `{organizationId,teamId,missionId,eventId,versionBefore,versionAfter,pausedBefore,pausedAfter,committedAt}` with versions decimal strings; accepted result flips the flag, increments shared task_intake_version exactly1 and changes Mission updated_at. GET `/receipts/{key}` exact `{receipt:Receipt|null}`, only matching current actor/scope/key. Preserve original accepted receipt across later lifecycle/intake changes; reauthorize first, receipt lookup before mutable eligibility/staleness/no-op checks. Changed-body key reuse conflicts; retry never produces a second effect.

Writable for Team DRAFT/ACTIVE and Mission CREATED/READY/RUNNING/WAITING_APPROVAL, version<Long.MAX_VALUE. Ordered blockers TEAM_ARCHIVED,MISSION_NOT_EDITABLE,REVISION_EXHAUSTED,UNKNOWN_STATE. Unknown states fail closed. Both pause/resume share eligibility; archived/terminal Missions do not get an implicit exception. Current paused state alone is not a blocker.

Command transaction READ_COMMITTED: lock organization→account→membership→Team→Mission, reauthorize after locks, exact scoped resolution then own receipt recovery; current snapshot/eligibility checks before new update. Serialize with existing Task Create and Draft Edit parent locking. An intake change invalidates earlier Task Create version and Draft Edit fingerprints; accepted historical replay still succeeds with current authority. Task Create must also fail closed at Long.MAX_VALUE before incrementing and allow only known Team DRAFT/ACTIVE statuses; retain historical replay ordering. No unrelated task or Mission lifecycle changes.

V018 adds only scoped actor/key mission_intake_receipts with unique eventId, canonical body digest, immutable original response and created_at, FK exact Mission scope and human account. No seeds/new roles. Receipt insert, Mission flag/version/time and one safe audit event MISSION_TASK_INTAKE_UPDATED with structured mission_id and metadata eventId/version/paused are atomic; rollback all on any failure. No private config or credentials in audit/log/DTO. Server timestamp clock_timestamp UTC. No separate history viewer or runtime worker.

## UI

ADMIN Mission Control successful view links “Quản lý nhận task” to `/workspace/:id/teams/:teamId/missions/:missionId/intake`. New responsive Forest view shows actual scoped names/status, current flag/version, next desired flag and explicit impact: stopping new task creation and draft edits, without claiming running work stops. Edit→review real before/after→unchecked acknowledgment “Tôi đã xem lại thay đổi nhận task.”→“Lưu thay đổi”. Cancel/back never writes; unchanged desired state cannot submit. Buttons “Xem lại thay đổi”, “Quay lại chỉnh sửa”, “Tải lại dữ liệu”, “Kiểm tra biên nhận”, “Gửi lại đúng yêu cầu này”. Review/fresh preflight must bind same current actor/scope/revision/fingerprint. Final receipt is historical; link back to scoped Mission Control.

Unknown/lost/malformed success freezes exact key/body, no automatic mutation or new key. Manual receipt read or identical retry only. After auth loss erase private context/review/frozen body; retain only opaque own actor/scope/key locator for explicit recovery after the same actor is restored, never write without captured body. Dirty navigation and native beforeunload guard; cancel subscriptions, actor/scope/generation/destruction fences on late reads/writes; recheck session+raw workspace ADMIN on initial load, focus/visibility, review/save/recovery. Clear returned private data before fresh authority check. No hardcoded status/count, no invented defaults. Keyboard/native controls, dark readable text and wrapping at1440/768/390.
