### Authority, interaction and closure

These are ordinary links to existing reads. Approval Center permits fresh enabled, credential-matching organization ADMIN/MEMBER metadata reads; ADMIN membership alone is not an approval grant. Detail decisions retain their existing action-specific eligibility/grant checks. Adding links neither expands backend access nor turns MEMBER into an editor. Preserve current auth guards, workspace authorization, scoped response validation, clear-on-authority-loss behavior and stale callback fences. A link can be visible without promising a successful unauthorized direct request. Never cache approval eligibility in navigation.

Preserve native router navigation, browser Back, dirty-discard and UNKNOWN-command leave handling on editors/decision forms. Compact menus retain keyboard operation, Escape, focus return, touch target size and readable wrapping at 1440/768/390. No GET or menu interaction issues a business mutation; navigation must not auto-submit, automatically retry an uncertain command or discard its recovery state silently.

Main should verify the full shell inventory, actual route targets/current organization binding and desktop/compact parity; click real links as ADMIN and MEMBER; cover revoked access and navigation away from dirty/UNKNOWN screens; verify existing approval group/page behavior and genuine empty/error states using real backend data. Do not seed production approvals or invent a runtime producer to populate the center. Existing local fixture updates and appropriate frontend/regression gates are routine engineering; do not claim authored cases or fixture rows as passed evidence. No backend/API/schema, graph or permission changes are needed. Main owns final copy/localization and visual evidence; no new Figma frame or exact-match claim is required.

**No unresolved product choice blocks this immediate slice.** The explicitly organization-wide Task Detail link resolves the scope ambiguity. ## Later candidate: DRAFT task dependency configuration

This remains a concrete missing workflow: Task Create persists up to 20 unique dependencies, while Task Detail only displays scoped dependency-ID links and input/owner commands preserve edges. Navigation completion does not close that gap. Prefer a later dedicated draft dependency editor over general graph planning, drag-and-drop graph manipulation or execution controls.

| Existing policy / fact | New bounded rule to freeze if selected later |
| --- | --- |
| Creation targets existing tasks in the exact organization/Team/Mission, all nine persisted states; max20, unique, no self. New identity with only outgoing edges cannot create a cycle. | Replace only the selected DRAFT task's outgoing dependency set; explicit empty set clears it. Reuse max20/scope/state eligibility; do not silently narrow candidates to DRAFT. Existing-task mutation needs genuine cycle validation. |
| Draft input/owner writes require current ADMIN, DRAFT task, Team DRAFT/ACTIVE, allowed Mission CREATED/READY/RUNNING/WAITING_APPROVAL and unpaused intake; unknown states fail closed. | Adopt the same conservative parent/task gate explicitly for dependency editing. It is a new command's rule, not a preexisting authorization to mutate edges. No MEMBER/Agent writer, approval grant, lifecycle transition or replanning. |
| Existing input/owner source fingerprints already bind sorted outgoing dependencies, respective revisions, saved task/parent state. Intake revision is not a graph/plan version. | Add an independent monotonic dependency revision to defeat A→B→A edge-set ABA; bind it reciprocally into input/owner fingerprints with versioned domains. A graph-wide concurrency token or complete transactional graph snapshot must protect cycle preflight; a source-only fingerprint cannot detect changes elsewhere on a candidate path. Do not repurpose intake revision. |

Required engineering contract before implementation:

- Define edge direction as “A depends on B.” Replacing A's edges with targets B is invalid if any B reaches A in the prospective scoped graph. Validate transitive paths of arbitrary depth, multiple targets, self, duplicates and max20; sorting is canonicalization, not cycle detection. Never truncate traversal and report success. Malformed/dangling/foreign graph rows fail safely without leaking metadata; specify safe conflict/unavailable responses and no implicit repairs.
- Serialize graph read/check/write with every participating writer, including creation, using the established organization → account → membership → Team → Mission → Task ordering. Current services use parent locks; main independently owns proving their sufficiency and any deterministic multi-task lock order. Reauthorize after waits. Test A→B and B→A concurrent commands, longer cycles and create/edit races against PostgreSQL. Two independently valid snapshots must not commit a cycle. No network calls under locks.
- Strict dedicated context/candidate/command/receipt DTOs, exact scoped IDs, safe current titles/statuses, literal paged search, no foreign IDs/names/path disclosure. Candidates and selected-set review are revalidated on save. Existing edges may not be silently dropped when a candidate becomes unavailable; either represent a safe unavailable selection for deliberate removal or block safely under a frozen rule.
- Fresh authorization and structural scope precede actor-scoped durable receipt lookup. Matching same-key canonical set/body replays original historical success before mutable blockers/fingerprints/cycle checks; changed canonical body conflicts. A new-key identical set is a no-op with zero effects. Freeze body/key for UNKNOWN; explicit receipt GET or identical retry only, with current authority and scope/actor fences. Preserve existing creation/edit/owner receipt formats and historical replay.
- Atomic edge replacement, task dependency revision/timestamp, immutable before/after event, receipt and safe Mission+Task-linked audit. Private scoped snapshots stay restricted; audit/Trace contain event/revision metadata, not dependency titles, raw private references or request bodies. Failures roll everything back. Preserve input/owner revisions, status/pending fields, intake counter, grants and execution state. No synthetic history baseline or mandatory new history screen.
- Prove cross-editor stale detection and ABA even with equal timestamps; same/different-key races, rollback, restart durability, strict wire/privacy, revoked-authority recovery and real responsive review/dirty/UNKNOWN behavior. New dependency receipts prove configuration history, never scheduling readiness or executed prerequisites.

Routine schema/token naming, canonical encoding, locking strategy, traversal algorithm, endpoint naming and test fixtures need engineering resolution, not another product approval. Genuine product choices arise only if scope expands: editing non-DRAFT tasks, changing dependency status eligibility, cross-Mission edges, automatic state/blocker recomputation, runtime replanning, or tolerating/repairing preexisting invalid graphs. Default this later slice to fail closed and configuration only. No provider credentials block either bounded slice; actual execution, dispatch pause, task-scoped approval discovery and typed missing-input resolution remain separate work.
