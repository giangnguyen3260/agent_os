# Prepare a worker-attested unsent failure for a fresh explicit Start

This opt-in backend slice uses `agentos.execution.unsent-recovery.enabled=true`, default false. It adds a worker-owned no-send attestation and an ADMIN preparation API. It does not resolve UNKNOWN, retry a provider call, resume an old lease or automatically Start work. No operator-provided outcome assertion or arbitrary task status is accepted.

When enabled, the actual worker records execution_unsent_failure_evidence atomically with its definite pre-handoff failure transition. It pins organization/Run/Attempt/fence/dispatch and immutable request SHA. The sent/unknown path does not write it. Failure during a pending PAUSE follows existing unsent pause handling instead. Existing historical failures get no attestation backfill and remain unavailable to this command. Runtime DB provisioning must grant the trusted worker the dedicated evidence insert privilege before enabling; no deployed permissions are changed here.

GET/POST `/api/v1/organizations/{org}/execution-runs/{run}/unsent-recovery`. Current enabled credential-version-matching ADMIN required, organization mutex held. GET returns candidate Run/revision/fingerprint, not a promise that final parent eligibility will remain available. POST requires CSRF and exact strict `{idempotencyKey,expectedFingerprint}` wire reused from the existing approval command record. Unknown/coerced/duplicate/missing fields reject.

The candidate must have Run/Task BLOCKED with trusted EXECUTION_UNAVAILABLE reason and exact worker attestation joined to latest terminal FAILED Attempt, latest invalidated claim/fence, FINISHED source dispatch at Run revision minus two and immutable request SHA. Every dispatch must be FINISHED; no unresolved Attempt/claim/reservation may remain. The failed Attempt must have no model usage or provider handoff and no nonzero expense. Foreign scope, absent/corrupt linkage, UNKNOWN and ambiguous remote evidence deny. Source revision must leave five increments for prepare→claim→finish→review→ACCEPT.

Preparation atomically changes only that Run to CREATED at revision+1 and Task to READY with pending metadata cleared. Existing Start eligibility revalidates accepted graph/configuration/dependencies/owner, active parents and OPEN Mission control before commit. Failure rolls back state and receipt together. No dispatch, Attempt, lease, budget hold, provider call, new Tool approval or automatic acceptance is created. Historical Tool effects/approvals and model history stay recorded; a new revision needs fresh preflight/selection. This is readiness restoration, not guaranteed provider availability.

V061 retains actor/org/key receipts with exact source/result revisions, fingerprint and database recorded time. Exact replay after fresh ADMIN authentication returns historical result without preparing twice, even if mutable state has advanced. Another Run/fingerprint under a key conflicts. Receipt canonical scope/revision hash is verified on replay; receipt is not present execution authority.

Local integration coverage includes once-only preparation without new dispatch, terminal-state/resource/UNKNOWN denial, another unresolved dispatch, nonzero failed-attempt charge, missing proof, headroom exhaustion, paused rollback/no receipt and revoked ADMIN. Cases are inherited by the required native PostgreSQL wrapper. This first slice has no UI or real worker-induced failure acceptance yet; positive fixture attestations are seeded, not claimed as actual worker observations. Matching-head CI and further real-worker acceptance remain separate gates. No generic UNKNOWN reconciliation, merge or deployment.
