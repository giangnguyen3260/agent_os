# Start preview binds approved Tool selection

A Run Start preflight now returns nullable `toolApprovalFingerprint`, identifying the exact text.metrics approval for that organization/Run/source revision. The Start page explicitly shows selected local text.metrics preprocessing and its zero-charge/transient-capacity convention, or says no Tool is selected. Unsupported/malformed fingerprints prevent private preflight rendering.

Start fingerprints with a selected approval are SHA256 over a versioned domain, original model preflight hash and approved Tool fingerprint. Both preflight generation and new Start validation use the same selection lookup inside the existing organization-serialized authorized transaction. Adding approval after obtaining an unselected preflight changes the required fingerprint: the stale command fails rather than silently executing a newly selected operation. Another Run/revision's approval does not affect the command. With no approval, the original preflight hash is preserved for compatibility with initial Task admission. Existing Start receipt replay still compares its immutable stored preflight hash before new mutable eligibility checks; no historical receipt rewrite.

This selection summary is not a fresh grant or approver authority attestation: worker checks remain mandatory at dispatch. Model request bytes and provider authorization/usage are unchanged. No new Tool/Skill capability, migration or automatic execution is introduced.

Local graph/runtime integration coverage includes original-versus-selected binding and exact Run/revision isolation; the required PostgreSQL wrapper inherits it. Mocked browser coverage checks selected summary and malformed selection refusal, retaining execution/dependency cases across three viewports. Existing controlled Vault approved graph and lost-reply acceptance exercise the new preflight hash in matching CI. Local build/lint/format/Java compile/import/diff checks are separate from native CI evidence. All PRs remain Draft/unmerged; paid-provider acceptance remains unverified.
