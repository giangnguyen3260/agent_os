## Behavior and authority

From actual Task Detail, current enabled credential-version-matching organization ADMIN edits existing DRAFT title, description/input, acceptance criteria and priority. Review before/after plus explicit unchecked acknowledgement, then final save. Owner, dependency edges, identity, lifecycle, pending fields, creation timestamp, execution/approval history and Mission intake revision remain unchanged. No transition to READY/RUNNING, blocker evaluation, provider call or new runtime flag. This is draft input/configuration editing, NOT S17 Provide missing input for a waiting execution or Pause mission. MEMBER uses existing Task Detail read, cannot use any new context/receipt/write endpoint.

Writable iff Task DRAFT, Team not ARCHIVED, Mission status CREATED/READY/RUNNING/WAITING_APPROVAL, task_intake_paused=false and task edit revision<2147483647. Unknown parent/task states fail closed. Existing paused intake conservatively blocks edits in this initial slice. GET still returns ADMIN same-org scoped blocked context with reason; no fabricated defaults. All parents require exact org+Team+Mission+Task joins. Parent mismatch404 after fresh org authorization; wrong/no membership403; disabled/stale sessions401/403 per existing boundary. Every read/write/replay reauthorizes. Use existing MissionCreateService authorization when possible; its method is package-private, so implementation in mission.application may reuse it or a new package may use equivalent org/account/currentmembership predicates with no shared security relaxation.
