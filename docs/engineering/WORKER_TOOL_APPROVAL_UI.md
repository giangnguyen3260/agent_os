# Worker Tool approval interface

Run details link CREATED Runs to `/workspace/{org}/execution-runs/{run}/text-tool-approval`. The opt-in backend may reject preview if the tool is disabled, the scoped grant is missing/expired or the Run is no longer eligible. The UI explains this without pretending a grant or approval exists.

The page loads the ADMIN-only exact preview, validates IDs/revision and bounded Unicode UTF-8 text and recomputes input SHA256 before displaying any private text. Text is escaped. An explicit unchecked acknowledgement enables approve; POST uses strict captured fingerprint/key and fresh ADMIN/CSRF. No raw input, grant or worker token is submitted. A verified reply must match every captured preview field. Only then does a separate link offer model request preview/Start; approval never automatically starts a Run or provider call.

Focus reload clears the checkbox and revalidates private context. A previously acknowledged approval remains acknowledged only for the same fresh fingerprint in the same page/account/Run session. Route/account changes erase prior context and acknowledgement. Pending ambiguous commands retain the exact key/body and private snapshot for manual identical retry; no new approval or Start link appears while unresolved. Navigation and browser unload warn about losing that correlation. Denial erases private text and pending content and explains that an already submitted command may have succeeded. A first definite rejection reloads and requires fresh acknowledgement; a rejection following ambiguity does not prove failure of an earlier send.

This is in-memory recovery only. Reloading/abandoning the page loses receipt correlation; the backend does not yet expose historical approval recovery or cancellation. The UI does not claim comprehensive recovery after Start. Tool success remains separate from model output ACCEPT. General model-directed tools/Skills remain unavailable.

Browser fixtures cover explicit approval/no automatic Start, escaped script text, focus acknowledgement, lost reply exact retry, ADMIN revocation privacy, tampered input SHA denial and first stale rejection on desktop/tablet/mobile. Build/lint/format are checked. These are mocked browser tests; real-backend browser approval→Start→worker acceptance and deployment writer-permission setup remain separate gates. No backend or migration changes in this slice.
