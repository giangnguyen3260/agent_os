## 1. Operation, authority and invariant

Replace only the source Task's entire outgoing dependency set. `A → B` means **A depends on B**. `[]` deliberately removes all dependencies. Maximum 20 selected targets, independently of search pages. Exact same organization + Team + Mission, existing task identities only, distinct IDs, no source ID. All nine persisted target statuses are eligible: DRAFT, READY, RUNNING, WAITING, BLOCKED, IN_REVIEW, COMPLETED, FAILED, CANCELLED. Completed/failed/cancelled targets are not hidden or implicitly removed. No owner/Agent/capacity/grant rule applies to targets.

Only a current enabled human account with matching session credential_version and current organization ADMIN membership may use any new endpoint, including reads and receipt recovery. MEMBER retains existing Task Detail access, with no new dependency-editor API access. Authentication failures use existing 401/403 boundary; foreign/no organization membership is 403 before wire parsing. Exact parent structural scope mismatch is 404 after organization authorization. A target outside exact scope is indistinguishable from missing.

Fresh write gate: source DRAFT; Team DRAFT/ACTIVE; Mission CREATED/READY/RUNNING/WAITING_APPROVAL; task_intake_paused=false; dependency_revision < 2147483647. Only this command's revision exhaustion blocks it. Intake counter, input revision and owner revision exhaustion alone do not. Context returns deterministic unique blockers in this order: TASK_NOT_DRAFT, TEAM_ARCHIVED, MISSION_NOT_EDITABLE, INTAKE_PAUSED, REVISION_EXHAUSTED, UNKNOWN_STATE. Apply known-state-specific reasons only to known statuses; UNKNOWN_STATE covers unknown task/Team/Mission status (including unknown statuses of graph nodes); unknown states never become eligible through default values. Known Mission statuses additionally include PLANNING, REVIEW, COMPLETED, FAILED, CANCELLED. Known Team statuses additionally include ARCHIVED. `canEdit` iff blockers empty.

No task lifecycle transition, pending_reason/waiting_since/resolver change, prerequisite completion inference, scheduling readiness, blocker recomputation, planning, dispatch, execution, approval or provider call. Dependency configuration receipts prove saved configuration only. No implicit repairs, dropped edges or synthetic baseline events.

## 2. Graph integrity and safe projection: explicit fail-closed choice

The graph is the actual complete Task graph in the exact organization/Team/Mission, including disconnected tasks and edges beyond every selected target's reachable path. Load every scoped task and every scoped edge, never only the source's neighborhood. Validate uniqueness, max20 outgoing per node, no self edges, both endpoints present in exact scope, valid persisted identities/revisions/timestamps/text, and acyclicity across the entire graph. Unknown but safely representable statuses produce UNKNOWN_STATE as above; malformed values are integrity failures. Detect cycles with an iterative visited/color algorithm or complete topological pass, O(V+E), arbitrary depth; do not recurse on the Java stack or truncate a traversal and return success. For prospective replacement remove the source's old outgoing edges, insert the desired set, then validate the full prospective graph again. Equivalently each desired target must not reach source, but full preexisting-graph validation remains mandatory. No cycle path or other involved IDs are returned in errors.

Do not hide invalid rows with inner joins: compare raw scoped edge records against the scoped task map before projecting. Also check, with UUID-only integrity queries, edges whose source or target is a scoped task but whose stored edge scope differs; any such edge is invalid. Never fetch foreign Task metadata to diagnose it. No global scan of unrelated foreign graphs is required. Composite V009 FKs/PK/check are strong storage protection but not substitutes for fail-closed application reads and corruption fixtures.

**Selected-row decision:** Context returns every existing selected edge as a safe, actual scoped Task3 row, even if parent/source gates currently block editing. No UNAVAILABLE row variant exists in this slice. Missing/dangling/foreign/malformed selected edge, invalid graph anywhere in scope, unsafe scoped metadata, duplicate edge, excessive outgoing count, or preexisting cycle produces safe HTTP500 TASK_DEPENDENCIES_UNAVAILABLE for context/candidate/fresh command. Return no partial context, null placeholder, raw reference, foreign title, foreign count, graph path, or repair/clear affordance. A corrupted graph cannot be cleared through this editor. Empty valid selection is exactly `[]`. Ordinary non-DRAFT targets remain safe rows, not unavailable rows. This deliberately favors safe failure over unresolved-reference disclosure. An authorized historical receipt remains recoverable without validating the current graph.

Private fingerprint-only input/criteria/pending fields retain existing legitimate multiline TAB/LF/CR values; their exact stored values are JSON-escaped into the private source tuple and never projected publicly. Do not apply the public single-line title/status validator to these fields or reject valid disconnected tasks solely because their input is multiline. Existing unsafe public metadata still fails closed; this slice does not broadly rewrite old command parsers or historical digests.

Safe task title: actual stored string, <=255 Unicode codepoints, blank legacy title allowed; never fabricate a title. Team name/Mission title: actual nonblank safe <=255. Safe text rejects ISO controls, DEL and unpaired surrogates. Status is actual safe nonblank <=50, with eligibility restricted to the enumerated states. Persisted negative/out-of-range revision, invalid/missing timestamps/IDs, unsafe title or malformed snapshots fail500. UI uses text binding and a visual `Không có tiêu đề` label for a blank title without changing the DTO or saved title.

Root: `/api/v1/organizations/{org}/teams/{team}/missions/{mission}/tasks/{task}/draft-dependencies`.

Page decimal `0|[1-9][0-9]*`, 0..100000; reject signs, whitespace, leading zeros, decimals/overflow. Query URL-decode once with strict UTF8, Java strip, <=100 codepoints; safe single-line text (no controls/unpaired surrogates). Case-insensitive literal substring on title; escape `!`, `%`, `_` for SQL LIKE with ESCAPE '!'; bind parameters. `query` response is the stripped string preserving its case. Reject malformed encoding, duplicate/unknown query keys, including encoded duplicates, and body.

POST max16384 UTF8 bytes; exactly one Content-Type application/json, optional UTF-8 charset only; exactly one UUID Idempotency-Key header, no comma-list. Strict UTF8 JSON object, exact required fields, duplicate detection recursively, no trailing JSON, missing/null fields, coercions or unknown fields. Dependencies array0..20; each exact DesiredTarget2; reject duplicate taskIds and source ID as400 before receipt lookup. Canonicalize valid dependencies by UUID text order, preserving each taskId/fingerprint pair. The same set supplied in different array order is the same canonical body. Strict command validation can occur before lookup; no *mutable* validation may precede a matching receipt. No GET/review/ack action issues POST.

Candidate eligibility is computed from the graph once per read: derive nodes reaching source using reverse adjacency, exclude them plus source before count/pagination. Do not per-candidate traverse the graph or materialize all candidate DTOs just to page. Reuse metadata already loaded for full-graph hashing to filter and order internal nodes once, then page and construct at most20 Candidate4 DTOs; alternatively use indexed scoped SQL with equivalent ordering/filtering. No extra full candidate DTO hydration is permitted; selected context is separately loaded from its actual edge set <=20; direct target reads are independent of current page/search. Full graph hashing/validation necessarily inspects all scoped graph nodes/edges; page size20 bounds returned candidates, not graph correctness. Use bounded batched graph reads, statement/resource limits and efficient adjacency maps. Resource exhaustion/timeout fails safely (500 TASK_DEPENDENCIES_UNAVAILABLE), never returns a partial graph or successful truncated cycle check. Add scope/title access index only if query plan justifies it; no invented correctness cap on graph size.

## 5. Canonical fingerprints, ABA and existing protocol compatibility

Use UTF8 JSON ordered tuples, no maps/object-key dependence, no locale formatting. JSON compact, no whitespace; preserve safe text codepoints without normalization, use JSON escaping, null distinct from empty; revisions decimal integers, booleans literals, times normalized with Instant.toString(). UUIDs lexical canonical strings. Sort task tuples by ID and edge tuples by (source ID,target ID), both canonical UUID text ordering. Hash with SHA256 lowercase hex. checkedAt, request time, search query/page, actor and receipt lookup do not enter source fingerprints.

Define scope tuple S = [org,team,mission,sourceTask].
Define node tuple N = [id,title,status,createdAt,updatedAt,task_edit_revision,task_owner_revision,dependency_revision] for **every** scoped task, including disconnected tasks, all target statuses and source. Define edge tuple E=[taskId,dependencyTaskId] for **every** valid scoped edge.
G = SHA256(JSON(["TASK_DEPENDENCIES_GRAPH_V1",[org,team,mission],sortedNodes,sortedEdges])). This is actual graph data, not intake version, max revision, selected-path hash, or a cached synthetic version. New tasks, unrelated task title/status/timestamp/revision changes and unrelated edge changes invalidate G even with identical source timestamps.

Source tuple T = [source title,description,acceptance_criteria,priority,raw owner_agent_id,status,pending_reason,waiting_since,resolver,createdAt,updatedAt,task_edit_revision,task_owner_revision,dependency_revision]. Raw owner identity participates privately; do not resolve foreign owner metadata. Parent tuple P = [teamName,teamStatus,teamCreatedAt,teamUpdatedAt,missionTitle,missionStatus,missionCreatedAt,missionUpdatedAt,task_intake_paused,task_intake_version]. Nullable legacy source fields remain null; waiting_since is normalized Instant or null.
Context fingerprint = SHA256(JSON(["TASK_DEPENDENCIES_SNAPSHOT_V1",S,T,P,G])). Context revision is source dependency_revision.
Candidate4 fingerprint = SHA256(JSON(["TASK_DEPENDENCIES_TARGET_V1",S,G,Ntarget])). Thus each target fingerprint binds its actual current title/status/times/revisions and the entire scoped graph. There is no independent candidate response graph token and no fifth target field. Even a candidate read is protected against off-path graph changes when its token is used at review/save. Candidate/context fetched from different snapshots may conflict conservatively; fresh review must resolve that explicitly, never silently retokenize an old choice. Context dependencies do not carry target tokens; direct candidate reads use this algorithm and are required for every desired target. A desired target token acquired later never replaces the context source token. Parent changes are protected by context fingerprint even if candidate token is unchanged.

Update existing source fingerprint domains **TASK_DRAFT_EDIT_SNAPSHOT_V2 → TASK_DRAFT_EDIT_SNAPSHOT_V3** and **TASK_OWNER_SNAPSHOT_V1 → TASK_OWNER_SNAPSHOT_V2**, preserving every old tuple element in its old position and appending source dependency_revision as the last element. Existing input fingerprint already binds owner revision; owner fingerprint already binds input revision. New dependency source fingerprint binds both. Dependency A→B→A increments revision twice and invalidates both existing editors even if all timestamps repeat; input/owner A→B→A similarly invalidates dependency tokens. No changes to old DTOs, command digest domains/encoding/canonicalization, stored receipt data, historical snapshot validators, history payloads or replay ordering. Old same-key requests carrying old fingerprint strings still hash/replay unchanged; fresh old-token requests conflict. Never reinterpret a historical fingerprint as a requirement to recompute current state. New revision0 on migrated tasks is valid and does not create synthetic history.

Dependency command digest = SHA256(JSON(["TASK_DEPENDENCIES_COMMAND_V1",S,actorId,expectedRevision,expectedFingerprint,sorted [[targetId,targetFingerprint],...]])); key is the receipt address, not a digest member. Store this version exactly. Same-key different expected token or target fingerprint is a different body even if desired ID set matches. Preserve TaskCreate's existing hash/canonicalization byte semantics; deterministic lock ordering must use a separate sorted lock list, not change its historical canonical body order.

## 6. Transactions, serialization and TaskCreate proof obligations

Write READ_COMMITTED explicitly. Shared mutex is `organizations(id) FOR UPDATE` held until transaction completion. Every participating writer of tasks/edges/graph-bound metadata must obtain this mutex before reading the graph and keep it through write+receipt+audit. This slice relies on existing input/owner/create writers already following it. Inventory other production task/edge/status writers before freeze; future writers must join this protocol. No claim that a fingerprint alone prevents concurrent cycles.

Dependency command sequence:
1. Fresh transport ADMIN check; parse strict wire. Begin transaction, lock org → human account → current organization membership (exact actor); evaluate enabled/credential/current ADMIN from fresh reads. Lock exact Team → Mission. Verify exact source structurally exists without obtaining an out-of-order Task lock.
2. Lock all current scoped Task rows in ascending canonical UUID text order, including source and all target/other graph nodes. This is one ordered level after parents. Org mutex prevents cooperating creates from inserting graph phantoms. Re-read current authority with new READ_COMMITTED statements after all waits, including parent/Task waits; reject revoked/disabled/stale actors before receipt replay. Re-read structural scope. Do not trust pre-wait entity/session cache. Locks acquired earlier are retained; reauthorization reads do not reverse lock order.
3. Lookup receipt PK(scope,actor,key). If found, validate safe stored provenance. Same digest => original Receipt200 with no current graph/state/target/fingerprint/no-op checks; different digest =>409 IDEMPOTENCY_CONFLICT. Receipt replay need not read/validate graph data. Merely locking task identities is not graph validation. No network calls under locks.
4. Freshly read full scoped graph/parents/source after locks; validate integrity, compute G/source fingerprint. Stale expectedRevision or expectedFingerprint =>409 TASK_DEPENDENCIES_CONFLICT. Then mutable blockers =>409 TASK_DEPENDENCIES_BLOCKED.
5. Resolve desired targets in exact scope, verify known statuses and every candidate fingerprint against current graph/metadata. Missing/foreign/self/cycle-ineligible desired target =>409 TASK_DEPENDENCIES_NOT_ELIGIBLE (strict self in wire already400). Changed target token =>409 TASK_DEPENDENCIES_CANDIDATE_CONFLICT. Stale source takes precedence if both tokens changed. Revalidate the complete prospective graph under held mutex/locks. Never rely on browser candidate preflight.
6. Compare canonical desired IDs with raw current scoped IDs. If identical =>409 TASK_DEPENDENCIES_NO_CHANGE, zero effects, no receipt/key reservation. Candidate fingerprints still must be valid; a new key cannot bypass source/gates by asking for unchanged IDs. Only genuine replacement/clear increments revision once.
7. Atomic replacement and persistence in section7, commit, return201. No exception-to-success swallowing. Database errors/timeout roll back; client treats uncertain response as UNKNOWN.

## 8. Errors and deterministic precedence

Use existing error envelope with empty details `{}` and generic safe server messages; frontend maps codes to labels, never renders raw exceptions. No target IDs, names, query text, counts or cycle path in error details/logs. Error order for POST: transport authority → strict syntax → locked fresh authority/structural scope → receipt digest/replay → graph integrity → source token → blockers → desired target eligibility/token → prospective cycle → no-op → atomic write. Unknown state blocks, malformed graph fails500. Structural source404 before receipt lookup; target404 only on direct candidate GET, fresh POST target misses use409.
