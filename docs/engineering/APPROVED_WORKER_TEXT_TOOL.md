# Explicitly approved worker text preprocessing

The optional text.metrics v1 path now has a trusted OpenAiExecutionFlow hook after dispatch.claim and before model authorization/credential access/transport. It operates on the exact current Task description, never model response text. It does not change the prepared model request. Human approval is separate from the existing Start command; no model text or Tool grant alone selects execution.

With text-metrics enabled, fresh ADMIN GET `/api/v1/organizations/{org}/execution-runs/{run}/text-tool-approval` returns a bounded private preview and fingerprint. Strict CSRF-protected POST accepts exactly `{idempotencyKey,expectedFingerprint}`. It pins Run source revision, current grant identity, UTF-8 input/hash, approver/credential version and recorded time in V060. No manual payload, worker token, capability or version is accepted. Approval requires current Start eligibility; stale previews conflict. Same-key approval replay is supported while the current Run remains eligible, not after Start; historical approval recovery/UI is not implemented in this slice.

After claiming the persisted dispatch, the worker resolves only the approval matching its source revision, reauthorizes the approver, verifies input and fingerprint, checks exact grant expiry/revocation and calls the existing gateway using its own fenced lease. Scope/control/configuration, capacity/zero-cost settlement and once-only effects follow the gateway contract. Missing approval means no Tool invocation. An approved operation cannot silently disappear when the feature is disabled: the disabled adapter path checks for matching persisted approval and rejects before provider handoff. Tool failure uses the existing pre-handoff failure path; it never retries a provider effect. A committed local Tool result remains historical evidence if subsequent model work fails.

The restricted disposable web runtime receives SELECT only on the approval table; native privilege assertions continue to deny INSERT/UPDATE/DELETE for this test role. A deployment enabling approval mutations requires a separately reviewed writer permission setup; this change does not broaden production DB grants.

Local validation: 28 graph/runtime integration cases including two new approval cases, real gateway invocation with pinned input/current lease, once-only replay/revocation, API strict shape and CSRF. Required native PostgreSQL wrapper inherits these cases. Compilation/import/format/diff checked. Existing real Vault worker suite will validate the no-approval path on matching CI; no new live-provider approval demonstration is claimed. No frontend change: approval UI, historical recovery and full real-backend browser approval→Start→worker evidence remain outstanding. No generic Skills, model-directed Tool calling, merge or deployment.
