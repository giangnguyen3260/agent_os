# Explicit UI for worker-attested unsent Run preparation

BLOCKED Run details link to `/workspace/{org}/execution-runs/{run}/unsent-recovery`, labeled as a condition check, not retry authority. The opt-in backend may reject UNKNOWN, missing proof, unsettled resources, nonzero failed-attempt usage/expense, exhausted revisions or disabled feature; no checkbox/mutation appears without a validated current candidate.

The page explains that preparation restores readiness only and never Starts, calls a provider or implicitly renews Tool approval. It shows the exact Run/source revision, requires a fresh unchecked acknowledgement, rechecks ADMIN before CSRF+POST and captures one exact fingerprint/key. Parent/graph/control eligibility is rechecked by the backend before committing; a candidate preview is not a guarantee that final preparation remains possible.

A validated response must match Run/key/captured source revision and result=source+1. It is displayed as a historical receipt, directing the user back to current Run details. It does not expose an automatic Start action or assert present eligibility. A separate fresh model preflight/Start remains necessary.

Ambiguous replies keep the exact in-memory body/key for manual replay even when a refresh no longer finds an eligible BLOCKED candidate. No new command replaces an unresolved one. First definitive rejection reloads and requires fresh acknowledgement; rejection after prior ambiguity cannot prove earlier failure. Focus refresh erases stale private data/acknowledgement, denial clears captured commands with an uncertainty warning, and account/route changes invalidate late callbacks. Navigation/unload warns about losing unresolved correlation. Reload/abandonment still loses the in-memory key; no browser persistence or general receipt listing is implemented here.

Local mocked browser coverage spans three widths: explicit preparation without Start, lost reply exact replay after state advances, unavailable/UNKNOWN candidate, exhausted revision, role revocation and fresh key/acknowledgement after first stale rejection. Retained Run history/evidence cases remain. Production build/lint/format and diff checked. Real-backend worker-failure→prepare UI→fresh Start acceptance and restricted runtime permissions remain future gates; no product-wide UNKNOWN reconciliation, merge or deployment is established.
