# DRAFT task owner configuration

Branch feature/task-draft-owner, base ef94202a4d98b16c0804f0f32a69c8fce7d89d85 (draft PR33). Current organization ADMIN assigns, changes or clears the configured Agent owner on an existing DRAFT Task. Configuration only: no execution, dispatch, Agent activation/authority, status/pending/input/dependency change. MEMBER retains existing Task Detail read but no new context/candidate/receipt/write access. This is an engineering scope selection under continuing screen-by-screen authorization, not invented historical product approval. No merge/deploy; Sonar paused.

## Policy and safe projection

Task DRAFT; Team DRAFT/ACTIVE; Mission CREATED/READY/RUNNING/WAITING_APPROVAL; intake unpaused. Only task_owner_revision is consumed, so exhausted Mission intake or task_edit_revision does not itself block owner changes. Ordered blockers TASK_NOT_DRAFT, TEAM_ARCHIVED, MISSION_NOT_EDITABLE, INTAKE_PAUSED, REVISION_EXHAUSTED, UNKNOWN_STATE, following existing Draft Edit known-state rules. Owner revision is integer0..2147483647; MAX blocks fresh writes. Unknown parent/task states fail closed. Legacy nullable input may remain null: this operation does not complete or validate input.

New target eligibility matches existing Task Create: current same-org, same-Team Agent with status DRAFT/ACTIVE, any safe level. No roster move, manager-only rule, grants or capacity claim. Candidate fields exactly {id,name,level,status,fingerprint}; fingerprint64lowerhex binds versioned scoped identity/name/level/status/updated_at. Agent public snapshot exactly {id,name,level,status}, no fingerprint. Name safe nonblank<=255codepoints, level/status safe nonblank<=50, reject ISO controls and unpaired surrogates. Team/Mission names safe nonblank<=255; taskTitle safe<=255 may retain blank legacy title. Text remains actual stored values, never examples.

Owner snapshot exactly {state,agent}: UNASSIGNED/null iff raw owner null; ASSIGNED/scoped public Agent snapshot even when current status is ineligible; UNAVAILABLE/null iff raw pointer exists but Agent cannot resolve in current org+Team. Never expose/query foreign names or raw foreign IDs. UNAVAILABLE can explicitly be cleared or replaced. No-op uses raw pointer, not public nullable projection. Allowed after states only UNASSIGNED/null or ASSIGNED/current eligible Agent. UNAVAILABLE→UNASSIGNED is a real clear, despite both public agent values null. ASSIGNED→same ID and UNASSIGNED→UNASSIGNED reject no-op. Current Agent eligibility changes do not silently rewrite existing assignment.
