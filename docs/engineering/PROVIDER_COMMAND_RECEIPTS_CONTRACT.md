# Internal provider command receipts

Date:1 November2026. Bounded implementation contract stacked on PR43. Scope is an authenticated internal JDBC service for durable equality/replay of the five provider-configuration commands CREATE, RENAME, ROTATE, DISABLE, ENABLE. It composes PR42 persistence and PR43 prepared command HMAC. It is not the public provider API/Receipt DTO: deployment policy, credential health/mask snapshots, capacity/rates, safe audit, external secret preparation/reconciliation, HTTP parsing and actual outer-completion privacy/UNKNOWN handling remain future application-boundary obligations. ACCESS_CHECK/MODEL_DISCOVERY are rejected; their queue/check/dispatch storage is absent. No provider/key/vault network work or raw secret enters this layer.

## Trusted input and transaction boundary

execute takes authenticated HumanIdentity, organization UUID, idempotency UUID, typed CommandBoundary.Command, prepared CommandBoundary.Metadata, and fresh-only CREATE connection identity / CredentialBoundary.Metadata for CREATE or ROTATE. The trusted caller must have prepared command metadata for exactly the same org/actor/command/borrowed secret outside all DB transactions. Metadata format cannot prove that correlation; never construct it from HTTP or expose its internal key identity/digest. Credential preparation is independently scoped; digest alone is not a grant. No default key service or secret store is injected.

Every call freshly authorizes enabled account, exact credential_version and current same-org ADMIN. Null actor401; foreign/missing org, MEMBER, removed membership, disabled account or stale credential version403 before receipt/resource lookup. Key UUID requires RFC variant2/version1–5, as do trusted submitted identifiers; parser spelling is a future transport concern. No actor-ID lookup argument: the receipt namespace is always (org, authenticated actor.id, idempotencyKey), across all five operations and targets. Another ADMIN cannot select another actor's receipt.

execute joins the existing transaction manager/DataSource with REQUIRED and actual READ_COMMITTED, non-read-only. Enforce active transaction, same bound JDBC resource, actual connection isolation and Spring read-only status before effects. Lock organization → actor account → organization membership; after waits read current enabled/version/role. For fresh mutation acquire scoped connection later; PR42's repeated same-owner locks are compatible. Joining callers must already obey this order. No REQUIRES_NEW/independent commit.

findOwn/probeOwn use one REPEATABLE_READ read-only snapshot with the same actual-context checks and fresh authorization, zero business writes/key/network calls. findOwn returns the safe historical result or null; probeOwn is an internal preparation read returning that result plus validated command metadata. Neither returns any credential reference/verifier. Absence is only a snapshot observation, never proof another transaction cannot commit.

All returned write results are provisional until actual outer commit. Every service-body domain/SQL/mapping/composition failure propagates a fixed cause-free unchecked ProviderReceiptFailure and marks joined work rollback-only. PREPARATION_REQUIRED is also a failure: a different historical key identity requires complete termination/rollback of the current transaction and release of its locks before re-preparation outside DB and a new transaction. A normal REQUIRED method return cannot release an outer caller's locks. No in-method retry or key resolution. Future orchestration retains the existing three-pass/10-second bounds.

## Receipt-first execution and exact outcomes

After authorization, validate supported command shape, key UUID and prepared command metadata, then lookup own receipt before current connection, revision/state/no-change, fresh CREATE ID or credential preparation checks. Null/unsupported command is INVALID_COMMAND. For a selected receipt, validate stored metadata/result/event structure before comparison. Different supported command-key identity yields PREPARATION_REQUIRED, not conflict or current-key fallback; the historical version is available only through authorized internal probeOwn, not the safe failure/result. Equal version + unequal computed prepared digest yields409 IDEMPOTENCY_CONFLICT via CommandBoundary's fixed-length constant-time comparison. A match returns the exact recorded historical result with replayed=true, with no current connection/credential metadata read or mutation. Fresh-only credential/CREATE identity may be absent on replay. This primitive trusts the caller's prepared equality proof, not command object equality as a substitute for secret HMAC.

If absent, validate fresh-only inputs and perform exactly one PR42 mutation through its transactional proxy. CREATE uses server-assigned UUID and prepared credential org/id/provider/revision1 matching the command provider/mode/options/name; no implicit upsert. Non-CREATE uses submitted command target and expected configuration revision; RENAME uses normalized command name, ROTATE exact next prepared credential revision, state commands retain credentials. Revision0 remains digest-valid but fresh non-CREATE mutation-invalid. Unexpected fresh CREATE-ID/credential arguments on other operations are invalid, not silently ignored. Errors retain PR42 stale/no-change/overflow precedence after fresh-only structural input checks. This internal ENABLE does not implement public provider-enabled/PRESENT-health gates.

Capture authoritative before state under the write locks, never by calling PR42 get() (which requires incompatible read-only RR). Select the scoped parent revision under FOR UPDATE and the actual corresponding retained event; validate its configuration/provenance before mutation. CREATE has no before. After the PR42 method returns, locate/validate its exact new event by org/connection/configuration revision, operation and actor. Insert one receipt in the same transaction. Forced parent/version/event/receipt failure or caller rollback rolls back every new effect. Same-key competing calls serialize under organization lock and see the first committed receipt; different actors have separate namespaces. Same key with different operation/target/body conflicts through the prepared digest before current mutable gates.

Internal Result exactly holds safe Receipt and replayed flag. Receipt has org,commandId,operation,connectionId,actorId,recordedAt,before,after. commandId is assigned once on insertion; recordedAt is PostgreSQL clock_timestamp() sampled after mutation/locks, not proof of the physical commit timestamp. PostgreSQL is the production clock authority. The H2 test fallback uses transaction-stable current_timestamp and supplies structural/rollback evidence only; it does not satisfy or prove post-lock wall-clock semantics. Native PostgreSQL observed-wait tests must compare receipt/event times to a clock_timestamp() lower bound sampled after the wait and before lock release. Configuration exactly contains organizationId,id,provider,credentialMode,name,workspaceId,state,revision,credentialRevision,createdAt,updatedAt. IDs are UUIDs, revisions positive long, timestamps DB instants. No key refs/digests/credential health/mask/current-observation/check or runtime-eligibility fields. No public JSON contract or magic health default; the future public receipt must freeze its separately sourced health snapshot atomically, rather than fabricate health from these historical rows. Internal result/probe/configuration types must be Jackson-ignore types and have redacted toString; safe serialization requires a future allowlisted public mapper.

## V023 storage and historical projection

Add provider_command_receipts only, plus supporting unique event constraints/indexes required for composite foreign keys; do not edit old migrations. Namespace PK(org,actor,idempotency_key), globally unique command_id, unique after_event_id. Row stores operation/connection ID, nullable before_event_id, non-null after_event_id and creation_event_id, digest_version/key_version/command_digest and recorded_at. No request body/JSON, raw secret/reversible envelope, external reference, credential-verifier metadata, copied arbitrary output or bearer capability. HMAC digest/version use strict PR43 grammar/domain; operation DB constraint accepts only the five implemented operations. before_event_id null iff CREATE. Organization/account FKs and composite (org,connection,eventId) FKs bind all three referenced events to the same scoped connection; before may have a different actor. creation_event_id must pin the exact scoped CREATE revision1 event, even for a legacy connection whose before/after revisions are already greater than1. A foreign key must prevent deletion of that creation event while any receipt needs it; before/after FKs alone are insufficient. No cascade/rewrite/delete API. Event immutability is a supported-writer rule, not DBA-tamper prevention.

Historical results project only pinned retained events, including the explicitly pinned scoped CREATE event at revision1 for createdAt, never current connection names/state/credential rows. Validate selected rows completely: exact scope, supported operation, canonical metadata, valid UUIDs, normalized safe names/provider/mode/workspace/state, positive bounded revisions, credential revision <= configuration revision and well-ordered times. Creation event must be CREATE at config/credential revision1, ENABLED, valid actor, same immutable provider/mode/workspace. after event actor must equal receipt actor; kind equals operation; CREATE after=creation event and before absent. Other before/after revisions are adjacent, same immutable fields/createdAt, with after time >= before time. RENAME changes name only; ROTATE advances credential revision exactly1 while preserving name/state; ENABLE/DISABLE changes only state to requested value. No-op event pairs are invalid. recordedAt >= after.updatedAt. Malformed selected receipt/event/creation relation fails closed generically, not null, partial projection or a current-state substitute.

Historical creator/previous actors are not freshly authorized to read their event: only the current requesting receipt owner is authorized. A later rename/rotation/disable, key-service outage or malformed current credential metadata does not rewrite or hide a valid historical receipt. Do not lookup current credential rows during replay/read. No code here deletes an external preparation after failure/unknown commit; reconciliation remains outside the DB transaction.

## Failures and acceptance

Fixed cause-free codes/status:401 UNAUTHORIZED;403 FORBIDDEN;400 INVALID_COMMAND/INVALID_KEY/INVALID_PREPARATION;404 NOT_FOUND for fresh authorized missing target;409 IDEMPOTENCY_CONFLICT/REVISION_CONFLICT/NO_CHANGE/REVISION_EXHAUSTED/CONNECTION_CONFLICT plus internal PREPARATION_REQUIRED;500 RECEIPT_UNAVAILABLE for incompatible transaction, selected corruption or unexpected storage/composition failure. PR42 statuses/codes may be safely translated/preserved, with no JDBC/SQL/input/nested cause in the exposed exception. This covers service-body failures only; transaction-manager completion/logging/unknown outcome privacy remains unimplemented and no HTTP route may expose the primitive until that outer boundary is tested.

Execute real Spring proxies/Flyway on H2 and native PostgreSQL. Cover all providers/five operations, exact before/after and immutable replay after later edits; historical-key mismatch release/reprepare; own/other actor and tenant authority, credential-version/role/reset/removal/disabled guards and observed lock-wait revocation. Test same-key identical/mismatching concurrent calls with one mutation/event/receipt and no external calls under locks. Verify event/receipt/outer rollback including caught failure marks outer rollback-only; incompatible joined contexts rejected. Force receipt-insert failure after CREATE and ROTATE. Exact schema/row allowlist, complete safe results and every persisted receipt column must be inspected; secret-sentinel absence is supplemental. Test named composite FK/namespace/event uniqueness, including deletion of the separately pinned CREATE event on a legacy connection whose before/after event IDs differ from creation, malformed selected metadata/events, missing receipt snapshot semantics, replay without current credential reads, no writes on reads/rejections and unchanged existing tables outside permitted provider mutations. Existing credential/command/persistence suites remain unchanged and pass. Authored counts are not passes. No merge/deploy; Sonar paused; session/CSRF one-way compatibility remains OPEN.
