## B1 — blocker: creation-event dependency is not protected by the proposed receipt FKs

Historical Configuration.createdAt requires the scoped revision-1 CREATE event. V022 provides unique (organization_id,connection_id,configuration_revision), but neither protects that event from deletion nor makes it immutable at the database level. The proposed receipt references protect only before_event_id and after_event_id. For an existing PR42 connection that has no CREATE receipt, a later receipt whose before revision exceeds 1 pins neither reference to the CREATE event. Deleting that otherwise unreferenced CREATE event would satisfy these FKs while making the durable receipt unreconstructable. No supported delete API reduces operational exposure but does not establish the proposed strong database retention for every reconstruction dependency.

Resolve by recording creation_event_id as a third scoped event reference on every receipt, with an immediate non-cascading composite FK (org,connection,creation_event_id), and validating that it is exactly the scoped CREATE event at revision 1. This adds a reference, not a duplicated snapshot or JSON. An equivalent explicitly specified database retention constraint is acceptable. Database constraints need not establish event immutability against DBA updates; the contract correctly distinguishes supported-writer immutability from tamper prevention.

Exact regression: create a connection through PR42 without a receipt; perform enough legacy mutations that the next receipt's before revision is greater than 1; insert the new receipt; attempt deleting the CREATE event and assert the named retention FK rejects it, with other constraints satisfied. Assert wrong-org/wrong-connection creation references are rejected by their named composite FK and a scoped non-CREATE creation reference fails selected-row validation. Preserve valid reconstruction/replay without consulting current parent or credential metadata.

## Accepted requirements and necessary evidence

1. **Event-reference reconstruction.** Scoped before/after FKs, unique after_event_id, and before-null iff CREATE are appropriate. Historical projection must use pinned events and retained creation identity only. A before event from another actor is legitimate; after actor must equal receipt actor. Test exact scope, CREATE revisions/state, operation/kind, adjacency without overflow, normalized safe fields, unchanged provider/mode/workspace, credential revisions, permitted per-operation differences and timestamp relationships. RENAME and state commands preserve credential revision; ROTATE increments it exactly one. Each malformed selected relation must fail closed without mutation. Include a legitimate cross-actor before event.

2. **Authoritative fresh before state.** Selecting parent FOR UPDATE and its current-revision event inside READ_COMMITTED resolves the prior incompatible-get problem. Validate the selected event against the locked parent's safe configuration and provenance before mutation; do not call read-only REPEATABLE_READ get(). Invoke the existing mutation through its Spring transactional proxy. Test event/parent disagreement and missing current-revision event, with zero lasting changes.

3. **Preparation exception and transaction termination.** PREPARATION_REQUIRED is correctly an unchecked failure that marks joined work rollback-only. It cannot itself end an outer transaction or release its locks. Caller must exit/roll back the entire transaction before historical preparation or opening the next attempt. Test standalone and joined execution: catching the exception leaves the outer transaction rollback-only; no normal-return continuation is treated as permission for outside-DB key preparation; a subsequent attempt occurs only after termination. Same-version comparison must use CommandBoundary.compare; different versions must never be translated to digest mismatch or current-key fallback. Historical version hints remain confined to authorized probeOwn.

4. **Unprovable preparation correlation.** The contract explicitly and correctly trusts a caller to prepare metadata for exactly actor/org/typed command/secret outside all DB transactions. CommandBoundary.Metadata proves syntax only; the service cannot establish cryptographic correlation from those arguments. Credential metadata provenance is likewise unprovable here. Preserve the internal-only construction boundary, no HTTP mapping, Jackson-ignore types and redacted diagnostics. Acceptance must not describe this service as independently authenticating supplied digest provenance.

5. **Receipt-first semantics.** After authorization and structural checks, matching receipt replay precedes current connection/revision/state/no-change and fresh-only ID/credential validation. Test replay with absent fresh preparation, later rename/rotation/disable, malformed current credential metadata and unavailable key/vault dependencies. Instrument SQL/dependencies to establish no current-parent/credential query or key/vault call on historical reconstruction. Same namespace across all operations/targets; different actors remain separate. Unsupported ACCESS_CHECK/MODEL_DISCOVERY must reject even though CommandBoundary represents them.

6. **Atomicity and actual transaction context.** Test actual Spring proxy REQUIRED joining and rejection of incompatible isolation/read-only/resource contexts. Force receipt insertion failure after CREATE and ROTATE and verify parent/version/event/receipt plus caller marker rollback. A caught service-body failure must leave outer work rollback-only. Native PostgreSQL concurrent identical requests produce one mutation/event/receipt and exact replay; differing commands under the same key produce one winner and one equality conflict. Include a race exposing a historical-key receipt and a lock-wait account/version/membership revocation.

7. **Internal Configuration scope.** The exact configuration projection is coherent and excludes health/mask/key references/digests. recordedAt is a post-lock DB wall-clock observation, not a physical commit timestamp; returned values are provisional until outer commit. Public health snapshots, policy/capacity/rates/audit, HTTP and transaction-completion/UNKNOWN privacy remain separate acceptance gates. Future public mapping must freeze health at its committing boundary, never manufacture historical health from today's state. No public DTO or end-to-end feature acceptance follows from this slice.

8. **Read authority and storage evidence.** findOwn/probeOwn authorize enabled credential-matching same-org ADMIN before lookup in one read-only REPEATABLE_READ snapshot. Test other ADMIN/tenant privacy, absent-as-snapshot semantics, corrupt selected metadata, zero writes/network calls, exact receipt column allowlist, namespace/command/event uniqueness and all scoped reference constraints. Probe may return command metadata internally but never credential reference/verifier. Existing credential, command and persistence suites must remain unchanged and pass; authored counts alone are not execution evidence.

## Clock R1 follow-up — bounded production-clock evidence

Date: 1 November 2026. Bounded reread of the revised clock paragraph and related timestamp validation/acceptance requirements only; no full source audit. **PASS at requirements level.** PostgreSQL is explicitly the production clock authority: recordedAt uses clock_timestamp() sampled after mutation/locks, and is not asserted to be the physical commit timestamp. H2's transaction-stable current_timestamp fallback establishes structural/rollback behavior only and cannot establish post-wait wall-clock behavior. This scope distinction is coherent and does not weaken the PostgreSQL production requirement.

For the native observed-wait regression, make the ordering explicit in execution evidence: observe the receipt writer blocked behind the holder; have the holder sample clock_timestamp() after that wait has been observed but before the holder commits/releases its lock; then permit the writer to proceed. Assert both receipt.recordedAt and after.updatedAt are >= that holder lower bound, and recordedAt >= after.updatedAt. The bound must precede release; sampling only in the writer after acquisition would not independently demonstrate exclusion of transaction-start timestamps. Establish the writer transaction began before the holder sample so the test discriminates transaction-stable current_timestamp from the required clock_timestamp(). No arbitrary sleep alone establishes observed blocking.
