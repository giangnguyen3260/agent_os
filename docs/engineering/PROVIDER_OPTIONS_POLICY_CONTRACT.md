# Provider deployment policy and public options read

Date:2 November2026. Bounded follow-up to PR45 closure. This slice delivers only GET /api/v1/organizations/{organizationId}/provider-connections/options, a durable deployment policy, shared read admission and an explicit trusted operator CLI. It does not expose connection/credential/receipt/check/model writes or reads, secret-manager adapters/health, provider calls, Agent binding or runtime grants. Existing internal receipt/completion methods remain unchanged and must not be mistaken for policy-gated public commands.

## Policy storage and trusted writer

V024 creates an EMPTY provider_deployment_policy table: id SMALLINT PK with CHECK(id=1), positive BIGINT revision, NOT NULL booleans openai_enabled/anthropic_enabled/gemini_enabled with at least one true, required created_at/updated_at timestamptz, updated_at >= created_at. No seed row, startup provisioning, env-selected fallback, cached authority or implicit all-enabled default. An absent policy is valid unprovisioned storage; authorized options returns503 PROVIDER_CONNECTION_UNAVAILABLE. Selected malformed rows fail closed, never synthesize flags/revision.

Internal PolicyService has provision(explicit nonempty Set<Provider>), replace(expected positive long revision, explicit nonempty set), readTrusted() and options(HumanIdentity, UUID org). Provider is the existing CredentialBoundary.Provider enum, all three values supported. Internal Policy projection carries revision/flags/timestamps with redacted toString and JsonIgnoreType; it is not the public Options DTO. A plain INSERT arbitrates concurrent provision through singleton uniqueness. The losing call immediately throws a cause-free POLICY_ALREADY_INITIALIZED409 and does no further query in the aborted transaction; proxy/outer rollback must complete before the caller inspects state. No upsert can overwrite the winning selection. Provision always revision1.

replace uses REQUIRED READ_COMMITTED writable context, locks only policy id1 FOR UPDATE, validates selected policy, compares expected revision BEFORE no-op, then checks overflow before changing set. Missing/corrupt policy503; stale409 REVISION_CONFLICT; identical set409 NO_CHANGE; required increment at Long.MAX_VALUE409 REVISION_EXHAUSTED. Preserve created_at; sample PostgreSQL clock_timestamp() after lock, reject clock earlier than prior updated_at, update flags/revision+1/time atomically. Off/on ABA advances twice. All rejections/outer rollback preserve complete policy. Writer never locks org/account/membership afterward and invokes no network/key collaborator. H2's transaction-stable current_timestamp is only a structural test fallback, not production post-lock clock evidence. readTrusted and options require actual REPEATABLE_READ/read-only context and same bound JDBC resource; writes validate actual RC/writable context. Unsupported joined isolation/resource is503, never independent commit or REQUIRES_NEW.

Trusted concrete provisioning/CAS uses scripts/provider-policy-admin.py through operator-owned Docker PostgreSQL access, not HTTP or a user ADMIN grant. Require --providers explicit nonempty enum subset for provision/replace, canonical positive --expected-revision for replace; show accepts neither. SQL is constructed only from validated enums/booleans/int literals. Plain provision conflicts without overwrite. Replacement holds policy row before a second statement samples clock/evaluates expected/no-op/MAX and changes flags. CLI publishes a successful result only after psql exits successfully through COMMIT; process/timeout/parse uncertainty emits fixed unconfirmed outcome and never automatically retries. --sql-only prints only nonsecret policy SQL for inspection/tests. No cookies, DB password, token or provider credential is printed. No tool action in this delivery provisions the user's Mac/production; the runbook gives explicit operator commands and conflict/uncertainty readback.

## Shared security read admission

V024 also creates EMPTY provider_read_admission: organization_id/actor_id UUID composite PK, recent_requests VARCHAR(4096) NOT NULL, updated_at timestamptz NOT NULL. Org/account FKs may cascade security-row deletion; no membership FK, token/request body or business snapshot. Store only a canonical JSON array of at most120 nondecreasing nonnegative epoch-microsecond integers and the last observation timestamp. Rejection/corruption has no fallback/reset/clamp. This is security admission state, not business configuration, audit or a bearer capability. One bounded row per actor/org avoids per-request row growth; expired entries prune on the next accepted admission.

AdmissionService.acquire(HumanIdentity, UUID org) uses REQUIRED READ_COMMITTED, writable, same JDBC resource. Fresh auth before any mutation. INSERT ... ON CONFLICT DO NOTHING creates only an empty candidate row, then lock exact actor/org row FOR UPDATE. Recheck current enabled/version/ADMIN after waiting, using plain scoped SELECTs; never acquire earlier org/account row locks after quota lock. Sample PostgreSQL clock_timestamp() after lock. H2 current_timestamp is a structural fallback only. Any stored request or updated_at ahead of sampled time503; invalid JSON/type/count/order/overflow likewise503. Epoch arithmetic must not wrap.

Prune timestamps <= now-60 seconds (exact equality expires). If120 remain, throw RATE_LIMITED429 with Retry-After=ceil((oldest+60s-now)/1s), bounded1..60. Commit NO admission-table change on429, auth loss or storage/validation failure; in particular no newly inserted row, pruning or updated_at change may survive rejection. If fewer remain, append now and update array/updated_at. Same actor/org across API instances shares this row, so concurrent final-slot callers cannot exceed120. The same actor in another authorized org or another actor has an independent bucket. Quotas never replace authorization.

Admission commits separately before the policy read. An admitted GET that later fails shape/policy-read still consumes its security slot. Read projection itself is side-effect-free; session invalidation/touch and admission are deliberate security writes, not a claim that the entire HTTP GET writes no tables. Admission commit/read uncertainty fails503 and releases no policy; no automatic retry. No network/KMS/provider work inside admission or policy transactions. The future provider read surfaces must reuse this shared namespace rather than create per-instance counters.
