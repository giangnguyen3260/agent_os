# BA-03 provider connection API contract

Status: proposed comprehensive implementation design, 31 October 2026; not implemented, frozen, independently accepted or live-tested. Only this document and the companion [test cases](../qc/PROVIDER_CONNECTION_TEST_CASES.md) are delivered. No migrations, APIs, adapters, UI, runtime grants or Figma changes are claimed.

## 1. Scope and compatibility

Implements the scope of [requirements](PROVIDER_CONNECTION_REQUIREMENTS.md) subject to [BA-02 lifecycle authority](RUNTIME_LIFECYCLE_AUTHORITY_CONTRACT.md). The user's later all-three decision supersedes the lifecycle document's earlier unresolved provider selection. Ship OpenAI, Anthropic/Claude and Google Gemini adapters together. Installer selects a nonempty subset of enabled types without source rebuild; no implicit default. All three remain visible in options with actual enabled/disabled state. Multiple organization-scoped named connections may coexist. Disabling an adapter preserves its connections/history and permits metadata reads, rename, credential rotation and disable; blocks create, enable and new checks for that type. Configuration changes increment a deployment policy revision used by dispatch fencing.

The enabled set and revision have one authoritative durable singleton policy row shared by all API/worker instances, initialized by trusted installer provisioning with a nonempty subset and revision1. No process-local reload or cache can authorize work. Every set mutation, including off/on ABA, atomically advances the int64 revision; reject empty sets and overflow without mutation. Trusted policy writers lock only the policy row and never acquire organization/scoped locks afterward. Organization operations lock organization first, then policy, then accounts/memberships and scoped rows (§5); read enabled flags and revision together under that lock. Policy writers and org operations use the same row/mutex, including across instances. Instances unable to read/lock that authority are not ready for command/dispatch traffic and fail closed; stale local policy is not a fallback. Changes fence later page authorizations/publication but cannot cancel earlier authorized network work. Installer administration is a deployment control, not a new public route in this slice.

This slice manages credentials and explicit non-generation models-endpoint access checks/discovery. It has no generation/model-test endpoint. Save/rotate/enable/startup/read never calls a provider. No model IDs, prices, capability or billing guarantees are inferred. A models-list success proves only the observed list request succeeded at that time; it does not prove generation authorization, current availability, usable billing, quota or runtime grant. No claim that these requests are guaranteed nonbillable. Agent legacy provider/model strings remain requested configuration; no silent credential binding, activation, migration, failover or cross-tenant fallback. A separate reviewed Agent binding and budget gateway must enforce grants, accepted plans, claims, provider/model compatibility, reservations, actual usage and UNKNOWN reconciliation before any generation. Connection enable or check success cannot bypass the currently blocked activation path.

## 3. Authority, wire and limits

Root `R=/api/v1/organizations/{organizationId}/provider-connections`. All endpoints require the current enabled credential-matching human account and current same-org ADMIN membership. MEMBER and Agent/service callers have no access to even names, models, receipts or tests in this slice. A later scoped Agent-use read must be separately contracted. Session/CSRF and organization transport gates follow AUTH_RUNTIME and existing Task Owner command patterns. Authenticate/authorize before body/query validation; reauthorize inside transactions after waits. Foreign org denied 403; a connection/check not in the exact authorized org or a check not under the selected connection returns 404 without foreign lookup/projection. Own receipt means actor+org only, not another ADMIN's command.

All DTO field sets below are exact; nullable fields are required and explicitly null. IDs and Idempotency-Key use lowercase canonical RFC UUID v1–5 with valid variant. Revisions are canonical decimal strings `0|[1-9][0-9]*`, range 0..9223372036854775807; increments never wrap. Timestamps UTC RFC3339 with six fractional digits. Response uses existing `{data,meta}` ApiResponse with exact meta `{requestId}` (server UUID); failures use existing ApiErrorResponse `{error,meta}`, error exactly `{code,message,details}` with details always `{}` and the safe codes in §9, never an ad hoc provider body. Strict isolated parser: reject unknown/missing/duplicate fields, trailing JSON, malformed UTF-8, coercions, duplicate headers/query keys, unsupported media, non-UTF8 charset. POST accepts application/json with optional UTF-8 charset, one CSRF header, one Idempotency-Key, no query; body limit 8192 bytes before decoding. GET accepts no body. Path parsing is strict after authority gates. Do not change global Jackson coercion.

Safe name: strip surrounding Unicode whitespace, nonblank 1..100 codepoints, no ISO controls, U+2028/U+2029 or unpaired surrogates. Names need not be unique; identity is UUID. apiKey is 1..4096 ASCII visible bytes excluding whitespace (0x21..0x7e), preserved exactly, never stripped or prefix-validated; syntactically valid is not provider-valid. No nonempty minimum designed to claim entropy. `workspaceId` null or `wrkspc_` plus 1..128 ASCII alphanumerics; reject CR/LF and header syntax. Options exactly `{workspaceId}` for Anthropic and `{}` otherwise. Model IDs are untrusted safe single-line strings 1..256 codepoints; displayName null or safe 1..255; reject invalid selected provider payload rather than truncate identifiers. IDs are opaque, never URLs or executable markup.

List pages fixed20, page optional default0, canonical integer 0..100000; only `page` allowed. Stable order createdAt DESC,id DESC with actual safe-integer total; concurrent offset pages may shift, so not a snapshot guarantee. 100 connections/org maximum including disabled. Reads 120/min/account/org; fresh metadata writes 30/min/account/org. Ingress applies a separate bounded request-size/concurrency guard before parsing and must not record bodies. Persisted checks: 6/min/account/org, 12/min/org and one nonterminal check/connection. Sliding windows; 429 Retry-After rounded up and capped60 seconds. Valid historical replay/receipt lookup bypasses fresh-write/check quotas, subject to read/ingress protection. Quotas never substitute for authorization.

## 4. Exact public DTOs and routes

Types below are schemas, not permissive examples. `Connection` exactly `{organizationId,id,provider,credentialMode,name,options,state,revision,credentialRevision,credentialState,credentialMask,createdAt,updatedAt}`. state ENABLED|DISABLED. credentialState PRESENT|UNAVAILABLE; PRESENT means structurally present authenticated-at-write storage, no known integrity failure for the active envelope version, and locally available fresh usable key-service/key-version health evidence as defined below; otherwise UNAVAILABLE. Neither state is per-read cryptographic verification, remote credential validity or a guarantee of the next unwrap. credentialMask is the constant `"••••••••"` when PRESENT, null otherwise: no prefix, suffix, length or fingerprint disclosure. No secret/key-reference fields. Metadata availability can change independently of configuration revision.

Health projection is side-effect-free. GET/list/detail/receipt never unwrap/decrypt, call KMS/provider, refresh health or enqueue work. A trusted independent key-health observer makes bounded out-of-transaction key-service checks and publishes safe per-key-version usable/unavailable observations with observedAt/validUntil (maximum60s validity, evaluated using database clock). Startup/restore with no fresh observation is UNAVAILABLE. An independent integrity record is bound to active credential/envelope storage version; authenticated encryption/rewrap records verified-at-write, dispatch unwrap records any integrity failure via a version-CAS transaction. Latent tampering may remain undetected by GET until that defined unwrap path; no optimistic claim of fresh cryptographic authentication. Missing/malformed storage is immediately UNAVAILABLE. Key-health expiry, unknown or failure yields UNAVAILABLE without causing metadata-read failure. Observer publication holds no network call under DB locks; credential integrity writes follow §5 order and cannot replace a newer envelope's evidence. Known integrity failure remains unavailable until a replacement or separately authorized verified repair, never cleared by GET or a key-health success alone. Observations contain no credential values and do not increment configuration revisions. Connection receipt snapshots freeze health/mask as observed at commit forever; replay/GET receipt never recomputes them. Safe metadata, rename and disable remain available during encryption/KMS outage, subject to separate command-HMAC availability.

`ProviderOption` exactly `{provider,credentialMode,enabled,optionsSchema}`; optionsSchema EMPTY|ANTHROPIC_WORKSPACE. `Options` exactly `{organizationId,policyRevision,providers}`; providers in OPENAI,ANTHROPIC,GOOGLE_GEMINI order. `List` exactly `{organizationId,page,pageSize,total,items}`; items Connection[]. `Detail` exactly `{connection,checkedAt,latestAccessCheck,latestDiscovery,currentObservation}`. latest fields nullable Check, selected by acceptance time then ID for their respective kinds, including pending checks. currentObservation NEVER_CHECKED|PENDING|OBSERVED_ACCESSIBLE|OBSERVED_DENIED|INDETERMINATE|STALE|UNAVAILABLE. Disabled/provider-disabled/unavailable credential => UNAVAILABLE; latest access check absent => NEVER_CHECKED; revision/policy mismatch or expired result => STALE; then pending => PENDING; completed accessible/denied map accordingly, other outcomes INDETERMINATE. Discovery does not overwrite access-check observations. No `connected` or runtimeEligible boolean.

## 5. State changes and serialization

Create assigns IDs, state ENABLED, revision=credentialRevision=1; this permits only explicit metadata checks, never runtime. Rename increments revision only and rejects normalized same name. Rotate increments both revisions, preserves state/options/provider, replaces active encrypted key atomically; even identical supplied bytes count as an explicit rotation (no raw equality verifier). Disable/enable increment revision only; already-in-state =>409 NO_CHANGE. Enable requires enabled provider and PRESENT credential, but no passing test. Rename/disable remain possible during key-service outage; rotation/create require working encryption. Revision MAX blocks only commands requiring its increment; check dispatch remains bounded and independently fenced. Any config revision change supersedes pending checks, conservatively including rename. Re-enable never revives an old result. Provider policy changes invalidate checks even if toggled off/on (ABA).

Use READ_COMMITTED writes with lock order organization mutex → singleton policy row → existing globally ordered account/membership locks → connections → credentials → checks → page-authorizations, scoped rows in canonical UUID/ordinal order. Join lifecycle org-first protocol; no reverse acquisition. Policy-only writers follow §1. Health-only writers never obtain earlier locks after later ones. After every wait verify session credential version/account enabled/membership ADMIN and scope again. Structural scope and own receipt lookup precede current revision, state, provider policy, quotas, capacity and no-op checks. Existing receipt + matching digest replays despite subsequent rotation/disable/adapter outage; revoked authority denies. Different digest conflicts before mutable checks. For fresh commands validate gates, mutate, persist immutable safe event, receipt, safe audit and check outbox if applicable in one transaction; any failure rolls back all. No network, KMS unwrap/wrap or remote HMAC operation inside any DB transaction/lock interval. Dispatch secret preparation is outside locks followed by final locked authorization (§7). No other existing tables/configuration/receipt namespaces change.

### 5.1 Replay-first bounded two-phase key preparation

This protocol applies to every command; encryption preparation applies only to fresh CREATE/ROTATE. It does not authorize a browser to preserve/resubmit a secret after UNKNOWN.

1. Freshly authorize and strictly parse. In a short scoped read, find own immutable receipt and its digest/key version before any encryption preparation. Close the read transaction. If found, obtain/compute that historical HMAC outside DB locks, then take §5 locks, freshly reauthorize/scope-check, reread that receipt and constant-time compare the prepared digest. Match returns its exact original receipt; mismatch409. Neither encryption preparation nor current mutable gates are prerequisites for this replay.
2. If absent, read the fresh candidate's safe connection/envelope identity/revisions and current HMAC-key version, close that read, and prepare canonical digest outside locks. Only then pre-encrypt a fresh CREATE/ROTATE with server-assigned credential identity and candidate credentialRevision; retain no plaintext beyond request-local processing. These are speculative preparations, not authority or committed state.
3. Acquire §5 locks, reauthorize and reread own receipt first. A raced receipt with a prepared matching key/digest version replays or conflicts before any mutable gates. A receipt using an unprepared historical key/digest version requires rollback/release with no effects, then historical HMAC preparation outside locks and repeat step1. Never request a key while holding locks or substitute a current key for the receipt's version.
4. Only if receipt is still absent, evaluate fresh gates and compare all preparation inputs (credential identity/revision/provider/mode/AAD and HMAC version) before commit. Changed inputs reject with REVISION_CONFLICT (or the applicable fresh gate), never reuse an envelope for a different revision. Current HMAC-version change requires release and reprepare, not weaker verification. If encryption preparation fails, perform a fresh own-receipt probe before returning503; a raced receipt must be given the same historical verification path, so a valid replay with available historical HMAC does not depend on encryption health.

At most3 preparation/locked-validation passes and10s total server monotonic preparation budget per HTTP request; each external key-service call deadline is min(2s, remaining budget). Every mismatch/reprobe counts toward the bound. Exhaustion returns503 PROVIDER_CONNECTION_UNAVAILABLE with no mutation by this request; unavailable required historical HMAC returns503 KEY_SERVICE_UNAVAILABLE. Receipt absence is never proof another request cannot commit. Release all locks before preparation or retry; no background key preparation/resubmit, new command key or automatic network effect. A lost response after possible commit remains client UNKNOWN and uses secret-free GET receipt. Discard unused envelopes/digests/request buffers at completion. A current encryption outage plus available historical HMAC must permit replay observed in the initial probe or bounded race recheck; preparation exhaustion remains safely recoverable by receipt GET.

## 6. Secret storage and idempotency

Use authenticated reversible envelope encryption AES-256-GCM, cryptographically random 96-bit nonce per encryption under a unique random 256-bit per-credential DEK, 128-bit tag. Managed KMS wraps DEK; database holds ciphertext, nonce, tag, wrapped DEK, algorithm/schema version, immutable credential identity, managed KEK reference and version. AAD is unambiguous length-prefixed UTF-8 encoding of domain PROVIDER_CREDENTIAL_V1, organization ID, connection ID, provider, mode and credentialRevision. Backend deployment identity alone can unwrap; ADMIN API cannot. No key in source, DB plaintext, browser, environment sample, image or backup manifest. Production KMS key provisioned separately, least-privilege identities for encrypt/decrypt/rewrap, access audit without values, key backups/recovery tested. No plaintext fallback when unavailable. Rewrap under a new KEK uses authenticated decrypt/rewrap with CAS on envelope storage version; does not change credentialRevision or imply a new provider key. Keep old KEK versions until every active envelope and retained backup has a recoverable path; validate restore before retirement. A deployment without the KMS boundary fails closed for create/rotate/dispatch, while safe reads and disable remain available. No permissive developer default key.

Rotation retains only current active encrypted provider credential; old active envelope is deleted in the same commit and pending dispatch fenced. An already authorized in-flight call can have old bytes in transient memory; remote revocation must be done separately at the provider. Application disable/rotation cannot promise remote cancellation or provider key revocation. Encrypted backups remain under their retention/key controls; do not claim erasure from backups. Secret store recovery must restore envelope and key-version compatibility; metadata-only restores remain UNAVAILABLE.

New receipt namespace PK(orgId,actorId,idempotencyKey), across every operation/target in this slice; do not put body/operation in uniqueness key. Store `digestVersion`, managed independent `hmacKeyRef/version`, and HMAC-SHA-256 of canonical command. Never plain SHA256(apiKey/body), unkeyed fingerprint, suffix or low-entropy plaintext verifier. Canonical encoding: domain PROVIDER_COMMAND_V1, org, actor, operation, target (explicit null for create), then fields in §4 order, each typed null/string/object with length-prefixed UTF-8 bytes; options keys in schema order, normalized name, exact secret bytes, expected revision canonical strings. UUID spelling canonical; JSON formatting/key order irrelevant. HMAC excludes transport CSRF and Idempotency-Key (namespace already binds key). Constant-time compare using receipt's historical HMAC key version; never return/log digests or key references. Separate encryption and HMAC keys/permissions; receipt-only DB compromise must not enable offline guesses of weak keys. HMAC protects database-only compromise, not compromised application/key authority.

Receipt HMAC key versions remain available for receipt replay lifetime; no destructive retirement while receipts retained. If unavailable return503 KEY_SERVICE_UNAVAILABLE, never compute a weaker digest or treat it as a new command. Receipt GET does not need HMAC/encryption keys, because it returns only safe committed data. Receipts/events persist without expiry in v1; bounded paging does not delete them. Dedicated key retention/backup capacity is a deployment prerequisite. Raw request secret exists only transiently in TLS backend/browser input and provider auth header. Exclude bodies/headers from ingress/app/APM/trace/crash capture; exception messages and object toString cannot include commands. No raw-secret persistence in DB, queue/outbox, audit, Trace, local/sessionStorage, IndexedDB, service worker, analytics or URL. Set Cache-Control:no-store on all responses, suppress credential form autofill where feasible; avoid third-party scripts on these forms. Clear form/command references after submission, navigation or authority change; best-effort memory cleanup is not a guarantee against compromised clients.

## 7. Explicit asynchronous checks and outbound bounds

Check acceptance validates exact revisions, ENABLED state, enabled provider, projected PRESENT credential and rate/concurrency limits. Atomically write Check QUEUED, receipt, safe event/audit and IDs/revisions-only outbox. Internal immutable fields include actorId and acceptedActorCredentialVersion captured from the authenticated command (not a later account read), captured connection/credential/policy revisions, acceptedAt and queueExpiresAt=acceptedAt+60s. These authority fields are not added to public DTOs or audit payloads. Persist workerOwnerId, unique dispatchToken, startedAt and dispatchDeadline=startedAt+30s at the single QUEUED→RUNNING acquisition; never renew, transfer or reacquire this token to resend. Queue acquisition requires database clock strictly less than queueExpiresAt; equality is expired (FAILED/CHECK_EXPIRED, no send).

Each models page has a durable unique authorization identity `(checkId,pageOrdinal)` (ordinal1..10) bound to worker owner/token, captured revisions and request deadline. Under §5 locks, require the initiating actor's enabled account, exact acceptedActorCredentialVersion equal to the current account credential version, current same-org ADMIN, ENABLED connection/provider, exact captured connection/credential/policy revisions, active credential, RUNNING state, exact owner/token, no terminal result, no prior authorization for this ordinal and database clock strictly less than dispatchDeadline. Re-read policy row enabled set/revision while locked. Decrypt/prepare credentials outside transactions; the final page authorization after that preparation is the send linearization point. Unique page record is consumed once, not a reusable permission: redelivery or crash never grants another send for that page. Each next page repeats the full authority predicate; outbox duplication cannot acquire another worker/token/page send.

Use database clock sampled after lock acquisition/waits (not transaction-start time). Page request deadline=min(pageAuthorizedAt+10s, dispatchDeadline); connect deadline=min(3s, remaining request time). Worker checks time again immediately before network send and abandons expired permission; an already authorized request may still race disable/expiry across the network boundary. Final result publication takes the same §5 locks, rereads authority/policy/revisions and atomically CASes live check+owner+token plus snapshot only while database clock < dispatchDeadline. Exact equality is expired. A paused worker cannot publish ACCESSIBLE after deadline even before sweeper execution. Publication after expiry => COMPLETED/UNKNOWN TRANSPORT_UNKNOWN, no model snapshot; trusted finalization may record safe historical terminal status without advancing authority. Sweeper finalizes abandoned RUNNING by dispatchDeadline+5s, never resends. UNKNOWN/other terminal outcomes cannot be overwritten by late callbacks.

Loss of actor authority before any page authorization => FAILED/AUTHORITY_LOST with no send; after any authorization => SUPERSEDED/AUTHORITY_LOST. Connection/credential/policy mismatch => SUPERSEDED/REVISION_CHANGED. Deadline precedence: once dispatchDeadline is reached, UNKNOWN wins over arriving results or later invalidations for a nonterminal RUNNING check. A previously committed terminal result stays immutable. Before expiry, authority/revision fences take precedence over parsed provider success/error. Failure to establish the publication predicates must never publish a successful snapshot. No new provider call is allowed for trusted finalization. Queued and running authority loss is evaluated against the captured version even if a newly loaded account object carries its new credential version.

ACCESS_CHECK sends exactly one first models-list GET, validates schema and discards catalogue; MODEL_DISCOVERY is a separate explicit job. Discovery bounds:10 sequential authorized requests,1000 retained distinct models,1MiB decompressed bytes per page and4MiB cumulative decompressed bytes including discarded response bytes,30s operation deadline. No retries/redirects/fallback. Claude/Gemini requested page size100 with local item ceiling100; OpenAI sole page item ceiling1000. All page processing is whole-page: validate document, IDs, duplicates and continuation within bounds before staging it. Identical duplicate IDs may be deduplicated; conflicting metadata is a schema error. No part of a cutoff page is retained. Access checks apply the same first-response byte/item validation limits even though they retain no catalogue.

| Event, after authority/time predicates above | Terminal outcome / retained snapshot |
|---|---|
| Local per-page byte/item or remaining cumulative byte/retained-model bound crossed during response, no earlier fully validated page | FAILED/RESPONSE_LIMIT; no models (including OpenAI1001 items on its sole page, even with no cursor) |
| Same local cutoff during a later response with earlier complete pages | ACCESSIBLE/TRUNCATED; retain only earlier complete pages, discard entire current page; no further read/send |
| Fully consumed valid document exactly at byte/item ceiling | Accept full page; COMPLETE only with confirmed end, otherwise TRUNCATED if any local remaining budget/request/model bound forbids continuation |
| Complete pages retained but next send prohibited by request/count/byte/model budget (before deadline) | ACCESSIBLE/TRUNCATED; prior complete pages only |
| Fully validated final page, confirmed no continuation, no page/item loss | ACCESSIBLE/COMPLETE (including empty final catalogue) |
| Definitive provider/schema/cursor error actually observed within allowed parse bounds on any page | Mapped DENIED/FAILED; discard all staged models, never partial success |
| Ambiguous transport/request timeout on any page, or operation deadline reached even between pages | UNKNOWN/TRANSPORT_UNKNOWN; discard staged models, no late success |

Cutoff means detection that a bound would be exceeded, not merely reaching equality. Do not read/decompress beyond the configured cap to search for a later schema/error/end marker; a bounded parser may detect excess via framing or a one-byte overflow sentinel which is discarded and never accumulated as response content. If a definitive error was already observed before cutoff, use that error; otherwise cutoff rule wins even if unread bytes might contain an error. A later-page1MiB or remaining4MiB crossing is explicitly a local cutoff, not an unspecified transport error. COMPLETE requires complete validation and no retained-item loss, never merely an absent cursor in a truncated document. Publish TRUNCATED before dispatchDeadline under the same publication predicate or finalize UNKNOWN. Bounded streaming/decompression allocation must include parser buffers.

Provider cursors are opaque transient server-side data, max2048 UTF-8 bytes, URL-encoded only as query values, never URLs/paths. Reject absent/repeated/nonprogressing Claude last_id when has_more, repeated Gemini tokens, malformed arrays/types, invalid IDs, conflicting duplicates, unsupported success content type as PROVIDER_PROTOCOL_ERROR within parsing bounds. Unknown provider fields may be ignored; known fields require correct types. TLS verifies public host/certificate, port443, no userinfo/fragments. Dedicated egress allowlist permits only the three fixed hosts/paths and fixed pagination keys. Block loopback/private/link-local/reserved IPv4/IPv6 including DNS rebinding at actual connect; disable ambient proxy credentials, redirects and SDK background retries/telemetry. No arbitrary URL/header/project/model/prompt input. Inject mock transport for tests; no public test URL switch.

Timeout, EOF after possible send, crash after page authorization or uncertain delivery cannot prove invalid credentials or no send. Receipt remains committed independently of outcome. A deliberate new check after terminal UNKNOWN uses a new key and fresh review/revisions; no hidden retry. Requests authorized before disable may reach provider, but later authorizations/publication are fenced; no atomic remote cancellation guarantee.

## 8. Client recovery and historical truth

Client metadata command outcome and provider Check outcome are separate. Lost/malformed command response => local command UNKNOWN: clear apiKey and frozen secret body immediately; retain only actor/org/idempotencyKey/operation/connection locator. Never persist even that locator in browser storage. Poll own receipt explicitly: found means metadata/check acceptance committed; render historical safe receipt and separately refresh Detail/Check. Null means not found at that read, not proof of failure while a request could still commit. Authority loss clears private state and fences late replies; recovery only as same actor with restored fresh authority. GET receipt requires no key material and never re-executes.

Secret-bearing CREATE/ROTATE cannot offer automatic or frozen-body resubmit after UNKNOWN; do not ask for the old secret merely to recover. If receipt remains absent, surface unresolved state; a deliberate new create/rotation requires fresh review, fresh current state and a new key with warning that the original may still commit. ExpectedRevision fences rotation; create may produce a second named connection because names are not unique, so UI must reconcile the list before deliberate recreation. Metadata-only exact resend may use the same key/body, never altered body or automatic new key. Corrupt receipt decoding is safe503 and no mutation/re-dispatch. Receipt absence, local timeout, historical ACCESSIBLE and present envelope never imply current runtime eligibility.

## 9. Exact safe error semantics

Errors have fixed server-owned human-safe messages, existing request correlation metadata and codes only; no provider response text/headers, request URL with query, key fragments, SQL, ciphertext, key IDs or stack. Error envelopes never echo request fields. Provider Check errorCode is a nullable enum below, distinct from HTTP command failure. Remote errors still produce a committed Check result readable with HTTP200, not rollback of its receipt.

| Command HTTP | Code / condition |
|---|---|
| 400 | BAD_REQUEST: malformed exact wire, limits/types/media/URI/query |
| 401 / 403 | Existing UNAUTHORIZED / FORBIDDEN transport policy; no scoped details |
| 404 | NOT_FOUND: scoped resource absent |
| 409 | IDEMPOTENCY_CONFLICT; REVISION_CONFLICT; NO_CHANGE; REVISION_EXHAUSTED; PROVIDER_DISABLED; CONNECTION_DISABLED; CREDENTIAL_UNAVAILABLE; CONNECTION_LIMIT; CHECK_IN_PROGRESS; RESULT_NOT_AVAILABLE |
| 429 | RATE_LIMITED: fixed local limit, bounded Retry-After |
| 503 | KEY_SERVICE_UNAVAILABLE; PROVIDER_CONNECTION_UNAVAILABLE: safe storage/receipt/integrity/internal outage, rollback if not committed |

| Observed check event | outcome / errorCode |
|---|---|
| Valid HTTP200 model response | ACCESSIBLE / null |
| Provider401 | DENIED / PROVIDER_UNAUTHENTICATED |
| Provider403 | DENIED / PROVIDER_FORBIDDEN (scope/policy denial, not necessarily invalid key) |
| Provider429 | FAILED / PROVIDER_RATE_LIMITED (never invalid credentials) |
| Provider5xx | FAILED / PROVIDER_UNAVAILABLE |
| Other status incl3xx/404, wrong schema/type/cursor | FAILED / PROVIDER_PROTOCOL_ERROR |
| Proven DNS/connect/TLS failure before any request send | FAILED / NETWORK_UNAVAILABLE |
| Possible send then timeout/EOF/crash; ambiguous transport | UNKNOWN / TRANSPORT_UNKNOWN |
| Local byte/item cutoff without earlier complete pages | FAILED / RESPONSE_LIMIT |
| Local cutoff with earlier complete pages, before deadline | ACCESSIBLE / null, catalogueState TRUNCATED for discovery |
| Operation deadline reached, including before sweeper | UNKNOWN / TRANSPORT_UNKNOWN |
| Key unavailable before send | FAILED / CREDENTIAL_UNAVAILABLE |
| Queued deadline / authority lost before any page authorization | FAILED / CHECK_EXPIRED or AUTHORITY_LOST |
| Revision/policy/authority mismatch after any page authorization or revision mismatch before authorization | SUPERSEDED / REVISION_CHANGED or AUTHORITY_LOST |

A received5xx is a failed observation, not evidence the key is invalid. Late definitive responses cannot overwrite a terminal UNKNOWN; a new explicit observation is required. No generation effects or cost zero records are fabricated; this slice records no token/cost usage. Provider billing status stays unknown.

## 10. Persistence and delivery acceptance

Proposed new scoped connection, active credential envelope, immutable metadata event, actor/org/key receipt, check/dispatch and bounded model snapshot records; exact SQL migration is future implementation work. Composite tenant FKs, unique connection revision events, one active credential/connection, unique receipt namespace, one nonterminal check/connection and unique dispatch and `(checkId,pageOrdinal)` authorization identities must enforce the above under PostgreSQL, not just service checks. Internal persistence includes the singleton policy row (§1), independently maintained health/integrity observations (§4), and captured actor credential version, queue/dispatch deadlines, owner/token and page-authorizations (§7). No public field exposes these internal authority/key inputs. Safe audit contains organization/connection/command/check IDs, operation, revisions and enumerated outcome only. No credential envelope/options/body payload in audit or receipt internals exposed by read APIs. Read transactions use consistent scoped snapshots; malformed persisted selected records fail closed. Existing rows, Agent strings, grants, statuses, histories and old receipt digests are retained unchanged.

Future acceptance requires all companion cases with actual backend/PostgreSQL/restart/privacy/browser evidence, adapter fixture verification, opt-in authorized live models-only smoke evidence clearly separated from mocks, deployment key provisioning/recovery runbook, independent security/QC review, and parallel UI design handoff before UI implementation. This design adds no implementation or acceptance evidence by itself.
