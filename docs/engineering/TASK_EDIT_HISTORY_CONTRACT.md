## Decoder and paging clarification

Before snapshots preserve legacy text verbatim: title is a string <=255 code points (including blank), nullable description <=8000, nullable criteria <=4000, nullable priority is safe text <=255 (including historical unknown labels). Reject forbidden controls and unpaired surrogates; allow TAB/LF/CR only for multiline fields. After snapshots must match canonical nonblank stripped four-field edit command values, including known priority. Before and after must differ. Actor display name must be nonblank safe text <=255. These checks fail the selected page closed; this is structural validation, not cryptographic integrity or a database immutability guarantee.

Each response is internally consistent. Offset pages are fresh snapshots: a concurrent new edit may shift later pages and repeat a revision across requests. The UI explicitly explains that limitation; static paging has no duplicates, but no cross-request cursor/snapshot guarantee is claimed.

Existing organization transport authorization runs before controller wire parsing: a substituted organization without membership is403 even if its spelling is noncanonical. Authorized requests reaching the controller retain strict canonical-ID/page400 validation. Neither path exposes private history or writes business data.
