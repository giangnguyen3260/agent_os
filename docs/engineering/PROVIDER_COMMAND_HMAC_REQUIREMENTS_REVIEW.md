# Provider command HMAC requirements review

Status: independent BA/SA requirements freeze accepted for the bounded primitive, 1 November 2026. Reviewed PROVIDER_COMMAND_HMAC_CONTRACT.md as present over baseline 05a7f41. This is contract acceptance, not implementation, test execution or full-system acceptance. No contract or production source was changed by this review.

## Review basis and outcome

Compared the new contract with PROVIDER_CONNECTION_API_CONTRACT.md sections 4–6, PROVIDER_CREDENTIAL_STORAGE_AMENDMENT.md, PROVIDER_CONNECTION_PERSISTENCE_CONTRACT.md (including normative clarifications), and CredentialBoundary.java. Checked the persistence name-normalization implementation for compatibility. No blocking requirements gap remains in the six previously identified areas. Implementation may proceed within the stated exclusions.

| Earlier gap | Freeze/retest result |
| --- | --- |
| Frozen byte encoding | Resolved: literal domain, tags 0/1/2, unsigned four-byte big-endian lengths/counts, UTF-8 byte lengths, ordered object field-name/value pairs, no outer wrapper, and exact digestVersion mapping are explicit. Secret framing is string framing without constructing an immutable secret String or whole canonical stream. |
| Canonical field sets | Resolved for all seven operations: common prefix includes command key identity, org, actor, operation and explicit target; operation-specific fields and CREATE options are exhaustive. Unrelated fields must be absent/unrepresentable or rejected. Generated IDs, current state and transport fields are excluded. |
| Normalization/representation | Resolved: codepoint trimming matches persistence whitespace/space-character/U+FEFF handling; case/composition remain significant. UUID variant2/version1–5 and nonnegative long revisions are explicit. Zero is valid equality input without promising a successful mutation. Strict UTF-8 rejects unpaired surrogates. |
| Key identity/rotation | Resolved: command-specific key port and material, immutable bounded version identity included in MAC, historical verification without currentVersion lookup or fallback, managed-key entropy/provisioning obligations and encoded-key minimum are explicit. Credential-v2 is not reused. |
| Secret ownership | Resolved: synchronous borrowed char[] is unchanged on every outcome, with no retention; owner erases original/copies. CredentialBoundary gets a separate consuming copy. Primitive-owned temporary secret/digest buffers are erased, with an honest JCA/VM limitation. |
| Replay outcomes/metadata | Resolved: only successfully computed fixed-length constant-time comparison yields MATCH/MISMATCH. Invalid metadata, invalid commands, unavailable keys and unexpected computation failures have bounded cause-free errors; malformed metadata is rejected before key access. Canonical padded Base64 and historical version selection are fixed. |

The added key-identity prefix intentionally clarifies the older proposed API grammar. New vectors must use that prefix; credential-verifier-v2 vectors and any earlier proposed command bytes are not interchangeable with this format.

## Implementation acceptance and retest requirements

1. Commit independent Python hmac/hashlib fixture generation and literal byte-hex/digest expectations. Cover RENAME, ROTATE, DISABLE, ENABLE, ACCESS_CHECK and MODEL_DISCOVERY plus CREATE for OPENAI, Gemini, Anthropic null workspace and Anthropic non-null workspace. Include multibyte and supplementary names and fixed key identities. Java expected values must not be generated by the production encoder. Hex fixtures containing test secrets remain test-only; production exposes no canonical bytes.
2. For each operation, mutate every included field independently. Cover organization, actor, target where present, operation, key identity, each expected revision, provider/mode pairs, normalized name, workspace and exact secret bytes. Changing a provider must use another valid provider/mode/options shape when testing inequality rather than shape rejection. ENABLE/DISABLE and ACCESS_CHECK/MODEL_DISCOVERY must differ with otherwise identical inputs.
3. Verify normalization equivalence and persistence-compatible trimming, including U+FEFF and space characters; case and composed/decomposed names remain different. Test UTF-8 byte lengths, null versus string/object framing, boundary-shift collision resistance, name/secret/workspace limits and revision zero/Long.MAX_VALUE. Reject invalid UUID variants/versions, negative revisions, unpaired surrogates, unsupported shapes and extra secrets on every nonsecret operation. Invalid commands must not become MISMATCH.
4. Use key-port call counters to prove malformed metadata and invalid shape require no key access, and historical verify never calls currentVersion. Test current rotation/outage with historical success, missing historical key with no fallback, aliases of identical material under different valid identities, null/throwing/unusable keys and encoded keys shorter than32 bytes. Opaque keys must not be rejected merely because getEncoded returns null; use remains subject to JCA support.
5. Distinguish computed unequal MAC from malformed/noncanonical Base64, unsupported digest version and key failures. If the optional prepared/stored comparison is implemented, validate both metadata objects and reject incompatible digest/key identities without key access. Only compatible fixed-length digests receive the constant-time equality comparison; this helper is not authorization or receipt selection.
6. Assert borrowed-array nonmutation for success, mismatch, invalid command/metadata and key/computation failure. Inspect all command/metadata rendering and failure messages/causes for redaction. Review finally blocks for owned temporary-buffer erasure; tests alone cannot establish erasure of inaccessible JCA/VM copies. No helper may retain secrets in records, callbacks, fields or diagnostic causes.
7. Preserve CredentialBoundaryTest unchanged; run the new unit suite and required Java21 CI. Report actual executed tests separately from fixture/case counts. Source review must verify streaming encoding, domain/key separation, no production fallback/default wiring and absence of DB/HTTP/vault integration.

No implementation tests were run in this requirements review. The optional static comparator may be omitted; it is not a prerequisite for the primitive. Outside-transaction execution, deadlines/pass budgets, authorization, receipt namespace/rereads, actual commit semantics and secret cleanup by the future owner remain explicitly delegated obligations, not capabilities accepted here. No API policy, health or reconciliation expansion is requested.
