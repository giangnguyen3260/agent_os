# Provider command HMAC V1

Status: bounded implementation contract, 1 November 2026, stacked on PR42 persistence closure. This document freezes previously underspecified command encoding in PROVIDER_CONNECTION_API_CONTRACT.md sections5–6. The provider storage amendment remains authoritative. No HTTP route, receipt table/writer, deployment key adapter, vault integration, authorization, rate limit, reconciliation, provider call or UI is delivered by this primitive.

## Purpose and ownership

An explicitly constructed internal Java primitive computes/compares HMAC-SHA-256 for command equality. No Spring bean or production fallback. A separate command-specific Keys port supplies currentVersion() and key(version), with immutable version identities and managed keys of at least256 bits of entropy. Keys are outside the application DB and separate from credential-v2 verification keys. Historical receipt retention requires retaining its command-key version; missing history is an error, never current-key fallback. Version identity is an opaque ASCII token matching [A-Za-z0-9_./:@-]{1,256}; it identifies the key reference/version pair within this port, not a bearer credential. A managed opaque key need not expose encoded bytes. The key handle remains provider-owned and immutable for its recorded version. Every non-null getEncoded() result must be a fresh exclusively owned disposable copy, never shared with the key/provider or another invocation; the boundary may erase that returned copy immediately after initialization or on failure. Shared-backing-array Key implementations are unsupported and cannot be detected automatically by this primitive. Provider/JCA key use must not depend on the lifetime of that disposable copy. If encoded material is available, reject fewer than32 bytes; entropy and immutable identity remain provisioning obligations.

The API borrows a char[] secret synchronously for CREATE/ROTATE. It neither mutates nor retains that array, including failures. Request orchestration owns erasing the original on every exit and any copies; CredentialBoundary.prepare receives a separate disposable owned copy. This permits bounded historical re-preparation without preserving secrets beyond request lifetime. All primitive-owned secret byte/digest buffers are cleared in finally; JCA/VM internal copies cannot be guaranteed erased. No immutable String of the secret, whole canonical secret byte stream, output callback, database/network/logging dependency or exposed canonical bytes. Nonsecret command metadata and digest metadata render only redacted toString values; fixed cause-free exceptions never echo input/dependency diagnostics.

Outside-transaction key resolution, deadlines, three-pass/10-second preparation bounds and receipt-first fresh authorization remain orchestration obligations. This primitive does not claim to enforce them and cannot authorize a database command or provider use. No idempotency key is accepted here: the future receipt namespace remains (organization, actor, key), and selecting/rereading that immutable receipt is caller responsibility.

## Canonical values and valid shape

Scope is exactly organization UUID and actor UUID. All UUID inputs must have RFC variant2 and version1–5, rendered lowercase standard UUID text. CREATE target is null; every other operation requires its submitted connection UUID. Server-generated IDs, current mutable configuration, key-health/policy, external references, CSRF and Idempotency-Key are excluded.

Names trim leading/trailing codepoints satisfying Character.isWhitespace OR Character.isSpaceChar OR U+FEFF, matching PR42 persistence. Then require1..100 Unicode codepoints, no ISO controls, U+2028/U+2029 or unpaired surrogates. Preserve case and Unicode composition; no NFC folding. All string encoding is strict UTF-8, not replacement of malformed surrogates. Expected revisions are nonnegative Java long (0..Long.MAX_VALUE), encoded canonical decimal strings; zero is wire-valid for equality but fresh persisted mutation rules may subsequently reject it. API parsing of canonical UUID/revision spellings is a future transport concern, not permissive parsing in this primitive.

CREATE provider/mode pairs are OPENAI/OPENAI_API_KEY, ANTHROPIC/ANTHROPIC_API_KEY, GOOGLE_GEMINI/GEMINI_API_KEY. For Anthropic, options is exactly an object with workspaceId null or wrkspc_ followed by1..128 ASCII alphanumerics. Other providers have exactly an empty options object and no workspace. No arbitrary options map. Secret is1..4096 visible ASCII characters0x21..0x7e, exact bytes, no trim/prefix/entropy validity claim. Operations other than CREATE and ROTATE require absent secret (null); an extra secret, including empty array, is invalid. Fields not belonging to an operation must be absent/unrepresentable or rejected, not silently ignored. A command record never contains secret characters.

## Byte grammar and field order

HMAC input is the concatenation of typed values below, with no outer JSON, delimiters, field names or total-record wrapper. A null is one byte0x00. A string is byte0x01, unsigned32-bit big-endian UTF-8 byte length, then its exact bytes. An object is byte0x02, unsigned32-bit big-endian field count, then each field name as a string value followed by its typed value, in schema order. Lengths count bytes, not UTF-16 units or codepoints. All lengths fit the stated bounds; no signed overflow or streaming truncation.

Common prefix, in order: string literal PROVIDER_COMMAND_V1; string command HMAC key-version identity; organization string; actor string; operation enum string; target string or explicit null. Including key identity is an explicit clarification of the old proposed grammar and prevents metadata-version substitution even if provisioning accidentally aliases material. Stored digestVersion is exactly PROVIDER_COMMAND_V1 and maps only to this grammar; unsupported versions fail closed.

| Operation | Remaining typed values, in order |
| --- | --- |
| CREATE | provider string; credentialMode string; normalized name string; options object; exact secret as a string value |
| RENAME | expectedRevision decimal string; normalized name string |
| ROTATE | expectedRevision decimal string; exact secret as a string value |
| DISABLE | expectedRevision decimal string |
| ENABLE | expectedRevision decimal string |
| ACCESS_CHECK | expectedRevision decimal string; expectedCredentialRevision decimal string |
| MODEL_DISCOVERY | expectedRevision decimal string; expectedCredentialRevision decimal string |

CREATE options: OPENAI/Gemini emit object count0; Anthropic emits object count1, field-name string workspaceId and null/string workspace value. Null, empty string and empty object have different framing; invalid shape is rejected before any key lookup. No values from the current database or deployment policy enter this stream. The service layer must use the same normalized name when saving; this slice does not change PR42 persistence.

## Public Java behavior and errors

Provide prepareCurrent(scope,command,borrowedSecret) and prepareVersion(scope,command,borrowedSecret,keyVersion), returning only digestVersion/keyVersion/digest metadata. verify(scope,command,borrowedSecret,storedMetadata) uses the recorded version without calling currentVersion and returns MATCH/MISMATCH only after a successful fixed-length constant-time digest comparison. A no-key static comparison of prepared versus stored metadata may be offered for future locked replay, but must reject incompatible digest/key versions instead of treating them as equality. Historical key lookup failure is KEY_UNAVAILABLE, never MISMATCH/fresh success.

Metadata accepts only the supported digest version, valid key identity, canonical standard padded Base64 of exactly32 decoded bytes/44 characters. Reject unknown version, null, malformed/noncanonical/wrong-length digest as INVALID_METADATA before key access. INVALID_COMMAND denotes invalid scope/shape/value/secret; KEY_UNAVAILABLE denotes absent/throwing/invalid key service or unusable HMAC key; unexpected computation failure is INTERNAL_FAILURE. Fixed message, no cause or stack-based secret diagnostics. Constructors/validation use the same bounded failure types; no dependency exception text is exposed. MISMATCH is solely a successfully computed unequal digest. Internal digest metadata is never a public DTO, bearer token or usable credential; future HTTP must allowlist safe receipt fields, not serialize this type.
