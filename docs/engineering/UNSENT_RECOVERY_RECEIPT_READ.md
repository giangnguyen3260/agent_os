# Read a historical unsent preparation receipt

Opt-in GET `/api/v1/organizations/{org}/execution-runs/{run}/unsent-recovery/receipts/{key}` returns the existing receipt for the exact authenticated actor, organization, Run and idempotency key, or null when no matching receipt is visible. Current enabled credential-version-matching ADMIN authorization is revalidated. Cache-Control is no-store. The read-only REPEATABLE_READ transaction does not lock for mutation or create commands, dispatches or receipts.

Canonical source/result revision and stored fingerprint must match the original scoped preparation operation, including revision headroom. A historical receipt remains readable after mutable Run revision changes and is never current Start authority. A missing receipt leaves the operation outcome unconfirmed; it is not authorization to create a new command. Existing exact-command POST replay remains available. No schema or deployed privilege changes; receipt SELECT is already required by replay.

Integration coverage checks HTTP no-store, preserved source revision after Run advances, wrong Run/key non-disclosure, current-role revocation, corrupt fingerprint rejection and unchanged dispatch/receipt/revision counts. Cases are inherited by native PostgreSQL tests. Real Vault lost-response browser acceptance independently reads the committed receipt before exact replay and requires the original key and2→3 revisions; this native extension needs matching-head CI. This slice adds the API; user-entered receipt lookup UI is subsequent work. Controlled provider only; no paid OpenAI claim, merge or deployment.
